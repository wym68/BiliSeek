# BiliSeek

> **Seek and you shall find.** 寻则得之。

一个搜索驱动、以听为主、兼顾视频、**没有推荐和广告**的第三方哔哩哔哩 Android 客户端。

[![License](https://img.shields.io/badge/license-GPLv3-blue.svg)](LICENSE)

---

## 这是什么

Android 上有两类 B 站第三方应用：

- **纯音频播放器**（BBPlayer、BiliSound）干净无推荐，但**只能听、不能看**
- **完整客户端**（BiliPai、bilimiao、PiliPlus）能看能听，但**都带推荐首页**、以视频浏览为中心

本项目BiliSeek 汲取两者优势，构建全新使用体验

**注意：本项目所有代码均由AI工具开发。本人时间精力有限，目前仅以个人日常使用需求为开发目标，不定期进行功能完善和开发。如果您希望优化或开发功能，可自行fork魔改。基于此项目的二次开发请遵守GPLv3协议！**

### 核心亮点

1. **全站关键词搜索** —— 打开就是搜索框，搜遍全 B 站
2. **默认为听** —— 默认只下载音频轨，锁屏后台可听，省流量
3. **可切看视频** —— 一个按钮切到看模式，**切换无缝**：不重建播放源、不 seek、位置不丢
4. **没有推荐** —— 没有算法推荐流，入口只有搜索 + 你自己的歌单、行为记录与**关注**

> `seek` 一语双关：既是「搜索」，也是播放器进度条的 `seek`。

## 构建

### 环境

| 项                               | 版本                                       |
| ------------------------------- | ---------------------------------------- |
| minSdk / targetSdk / compileSdk | 26 / 35 / 37                             |
| AGP                             | 9.3.1                                    |
| Gradle                          | 9.7.1                                    |
| Kotlin                          | 2.4.10                                   |
| JDK                             | Android Studio 捆绑的 JBR（当前为 25；最低 JDK 21） |
| Media3                          | 1.11.0                                   |

> **AGP 9 内置 Kotlin 支持**，不要再声明 `org.jetbrains.kotlin.android` 插件——声明了会直接报错。

### 步骤

```bash
git clone <repo> && cd biliseek

# 配置 SDK 路径
echo "sdk.dir=$HOME/Android/Sdk" > local.properties

# 让 Gradle 用与 IDE 相同的 JDK，避免两套守护进程互相失效缓存
mkdir -p ~/.gradle
echo "org.gradle.java.home=$HOME/android-studio/jbr" >> ~/.gradle/gradle.properties

./gradlew installDebug
```

### 测试

```bash
./gradlew test                        # 全部 JVM 单元测试（离线）
./gradlew :core:network:test          # 单个模块
./gradlew connectedDebugAndroidTest   # 仪器化 + Compose UI 测试（需连设备/模拟器）
```

> ⚠️ **自动化测试绝不访问 B 站服务器**——一律用本地/模拟数据，真实接口由真人验证，
> 避免设备/账号被风控（`-352`）标记。详见 [AGENTS.md](AGENTS.md)。

### 发版

```bash
./gradlew assembleRelease             # R8 + 资源压缩
./gradlew archiveReleaseArtifacts     # APK + mapping.txt 归档到 releases/<versionName>/
```

Release 构建开启 R8，过度裁剪不会编译失败、只会运行时崩溃或静默解析失败——每次发版必须跑完整回归，
**没有 `mapping.txt` 就不算一次发版**。也可在 GitHub Actions 手动触发 `Build Release (draft)` 生成签名包与草稿 Release。
步骤见 [发版清单](docs/发版清单.md)。

CI：`ci.yml` 每次 push 跑 `./gradlew test assembleDebug`；`build-debug-apk.yml` 手动发布 debug APK。

> 干净机器的完整配置步骤（SDK 组件清单、环境变量、AVD、排障）见
> [开发环境搭建](docs/01-开发环境搭建.md)。

## 模块结构

```
:app              UI、导航、feature 控制器（搜索/动态/消息/评论/互动/弹幕…）、Room 数据库、下载
:core:network     风控接入与加固、WBI 签名、Cookie、写请求编排、B 站 API + DTO
:core:player      取流、DASH 组装、画质/音质选择、播放内核、PlaybackService
:core:ai          AI 总结：Provider 预设（OpenAI 兼容）、分块总结流水线 → Markdown；不认识 B 站
:core:asr         离线语音识别（sherpa-onnx + SenseVoice + Silero VAD）、模型下载 / 导入 / 校验
:design-system    主题、设计 token（间距/尺寸/圆角）、共用组件、封面取色
```

两条贯穿全局的架构约束：

- **播放器归 Service 持有**，UI 经 `MediaController` 访问。「默认只听」意味着用户大多数时间在别的 App 里、锁着屏，播放器生命周期不能绑 UI。
- **播放态由呈现态推导**：`PlaybackMode` × `PresentationMode` 两个正交维度，不变式「视频轨启用 ⟺ 存在可见 surface」由结构保证，无法被违反。

几条落地约定：决策逻辑抽成 `*Policy.kt` 纯函数并单测；远程数据（收藏夹、搜索结果等）不落库，只有用户主动存进本地列表才写 Room；
风控门控不阻塞 UI；WBI 签名在调用点完成；写请求的 `csrf` 由统一编排注入，调用点无法遗漏。
