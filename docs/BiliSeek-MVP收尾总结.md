# BiliSeek MVP 收尾总结

> 日期：2026-08-25  
> 范围：M0–M4  
> 结论：**MVP 闭环达成，可日常使用。** 有 3 项承诺未兑现，8 项已知缺口，下面逐条对账。

---

## 1. 对着选型篇逐条验收

选型篇定义的 MVP 闭环：

> 风控接入 → 扫码登录（非强制）+ 登录态续期 → 全站搜索 → 结果转音频条目 →
> 默认听（后台 + 媒体控制 + URL 缓存）→ **一键切看视频** → 基础歌单/库 + 首页空状态

| 选型篇的 MVP 项 | 状态 | 实测证据 |
| --- | --- | --- |
| 风控三件套（buvid + bili_ticket + WBI） | ✅ | 冷启动两次请求备齐；`GenWebTicket` 顺带返回 WBI 密钥 |
| buvid 激活 | ✅ | M2 补的，M1 时漏了 |
| DASH 取流 + 本地 MPD 组装 | ✅ | 「视频轨 6 条，音频轨 3 条」 |
| 取流降级链 | 🔸 | `dash → durl` 已实现；`html5` 兜底未做 |
| 听视频模式 / 纯音频播放 | ✅ | 默认即听，视频轨禁用 |
| **音视频无缝切换** | ✅ | 双向 buffering=0、seek=0 |
| 后台播放 / 系统媒体控制 | ✅ | 锁屏卡片可控 |
| **Web 扫码登录** | 🔸 | 二维码、轮询、三态转换均通过；**登录完成态待真人扫码** |
| **登录态续期 / Cookie 刷新** | ❌ | **未实现**，接口定义在但核心两步是空的 |
| 请求头策略（Referer / UA） | ✅ | 播放请求也带 |
| 网络策略 / CDN 选线 | 🔸 | 基本请求可用；未做选线 |
| 搜索即首页的信息架构 | ✅ | 三入口，无推荐页 |
| 首页空状态 | ✅ | 搜索历史 + 最近播放 + 播放热力 |
| 全站搜索 → 可播放条目 | ✅ | 含自动分页 |
| 一切皆歌单（多 P 折叠展开） | ✅ | 搜索结果一个 BV 占一条，点入展开 |
| 搜索输入智能路由 | 🔸 | BV 号直达可用；AV 号与 b23 短链识别了但退回关键词搜索 |
| 歌单 / 本地库管理 | ✅ | 增删改、加入、播放整单 |
| 播放 URL 缓存 | ✅ | 「playurl 命中缓存」 |
| 「默认听 / 一键切看」UX | ✅ | 原地展开不跳页 |
| 锁屏/切后台自动降回纯音频 | ✅ | PiP 属可见态不回落 |
| 登录非强制 | ✅ | 全程未登录跑完搜索到播放 |

**MVP 里 3 项没兑现**：Cookie 刷新（完全未做）、取流的 html5 兜底、AV/短链解析。

M4 还额外做了本不属于 MVP 的：播放队列、续播、画中画。

## 3. 全程发现并修复的缺陷

按严重程度排，都是实测撞出来的，不是 review 猜的。

| # | 缺陷 | 根因 | 阶段 |
| --- | --- | --- | --- |
| 1 | **buvid 未激活导致搜索恒为空** | 三层套娃：M1 漏了 `ExClimbWuzhi`；其 DTO 声明成 `String?` 但接口返回 `{}`，导致激活**从未成功**；`SearchData` 字段全有默认值，风控响应被反序列化成空对象而非 null | M2 |
| 2 | **分页滑几屏后崩溃** | B 站分页会返回重复 bvid（8 页累计 13 次），`LazyColumn` 重复 key 直接抛异常 | 修复期 |
| 3 | **SurfaceView 父容器冲突崩溃** | 同一 View 被展开态与全屏 overlay 两个 `AndroidView` 持有 | M3 |
| 4 | **续播完全失效** | `prepare()` 后的 `seekTo` 经 MediaController 异步转发被起播流程覆盖 | M4 |
| 5 | **接近结尾的续播＝「点了没反应」** | 61s 续播一首 62s 的歌，1 秒即播完 | M4 |
| 6 | `awaitReady()` 凭据失败时无限挂起 | `state.first { it is Ready }` 在 Failed 态永不成立 | M1 |
| 7 | `derivedStateOf` 无 key 导致分页永不触发 | 捕获了首次组合的空列表 | M2 |
| 8 | 标题 HTML 实体二次转义未解 | 接口返回 `&amp;quot;` | M2 |
| 9 | `release()` 未取消轮询协程 | 写成了空 `launch {}` | M0 |

### 三条值得记住的教训

**给 DTO 字段设默认值，会把「结构不符」变成「静默空值」。** 缺陷 #1 里，风控响应 `{"v_voucher":...}` 和正常响应的结构差异被默认值抹平，反序列化成一个字段全零的对象。表现是「搜索没反应」，排查成本极高。

**外部 API 的分页不保证不重复。** 缺陷 #2 的假设是「同一次搜索的不同页不会有相同条目」——这个假设从未被验证过，而它一旦不成立就是崩溃而非显示异常。

**「测出来没问题」有时是测法不对。** M3 一度判定 `BackHandler` 失效，实际是 force-stop 后没有播放内容、MiniPlayer 不可见、点击落空，状态压根没建立起来。M4 又一次把「续播到了结尾」误判成播放器卡死。**排查 UI 问题前，先确认前置状态真的建立了。**

## 4. 遗留项（按建议优先级排序）

### P0 — 影响日常使用

| 项 | 说明 |
| --- | --- |
| **Cookie 刷新未实现** | RSA-OAEP 算 `correspondPath` + 请求 HTML 页解析 `refresh_csrf` 两步是空的。**不做的话用户会周期性掉登录**，直接伤害「打开即用」 |
| **错误浮现慢（约 85 秒）** | `ensureReady` 全程持锁，后台预热与用户主动请求共用同一重试预算。断网时点播放要等一分半才报错。**需拆成两类重试策略：后台慢退避、用户请求快失败** |

### P1 — 体验缺口

| 项 | 说明 |
| --- | --- |
| 播放历史的时长恒为 0 | 显示「61s / 0s」，取流后未回写时长 |
| 加入歌单固定选第一个 | 缺「选择歌单」对话框 |
| 队列列表与拖拽重排 | 只显示「队列 N / M」，看不到完整队列；`reorder` 后端已实现（浮点 sortKey），差 UI |
| AV 号 / b23.tv 短链 | `parseSearchInput` 已识别，VM 里退回了关键词搜索 |
| 搜索无结果与风控无法区分 | 现在报同一条错误 |

### P2 — 未启用/未移植

| 项 | 说明 |
| --- | --- |
| 全屏播放 | 上滑手势有缺陷已移除；架构设计保留（顶层 overlay 方案），待重做入口 |
| 低端机降级 | 未移植 BiliPai 的 `BlurBudgetPolicy` / `MotionTier`，且无低端设备验证 |
| 流量策略（仅 Wi-Fi 拉视频） | 选型篇 P1 |
| 响度均衡 | playurl 已返回 `measured_i`，数据白拿着没用 |

## 5. 未验证的部分

**必须说清楚哪些没验到**，别把「没测」当成「通过」。

| 项 | 为什么没验 |
| --- | --- |
| **登录完成态** | 需要真人用 B 站 App 扫码。二维码生成、轮询、`86101` 状态、`Set-Cookie` 解析（单测）都验了，但没跑通一次真实登录 |
| **Cookie 刷新** | 功能未实现，无从验起 |
| **音频焦点**（来电、其他 App 抢占） | 模拟器无法真实模拟 |
| **耳机相关**（拔线暂停、蓝牙线控） | 模拟器无音频设备 |
| **低端机降级** | 无 2–4 GB 内存的老设备 |
| **Hi-Res FLAC 解码兼容** | 需大会员账号 + 特定设备（部分机型解码器只给 32 KiB 输入缓冲会崩） |
| **进后台回落音频的真机路径** | 模拟器 PiP 恒可用，看模式按 Home 总是进 PiP，回落分支只验了纯函数逻辑 |

前两项需要你的账号，后五项需要真机。步骤见[手动测试指南](BiliSeek-手动测试指南.md) Part B。

## 6. 下一步建议

按投入产出比排：

1. **拆开两类重试策略** —— 改动小，但影响所有错误路径的体感，是当前最扎眼的可用性问题
2. **你扫一次码，然后把 Cookie 刷新做完** —— 不做的话登录功能等于半残
3. **播放历史回写时长** —— 一行的事，界面上「61s / 0s」很显眼
4. **真机过一遍手动测试指南 Part B** —— 耳机、音频焦点、真实解码器只有真机能暴露问题

之后再考虑 P1 阶段的功能（收藏夹同步、下载导出 m4a、音质选择、响度均衡）。
