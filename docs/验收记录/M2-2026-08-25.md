## 发现并修复的缺陷

### 1. buvid 未激活导致搜索永远为空（阻断性）

**现象**：搜索接口返回 `code=0` 但结果为空，UI 显示「输入关键词开始搜索」，无任何错误。

**根因链条**（三层，逐层排查）：

1. **M1 遗漏了 buvid 激活。** 刚由 `spi_v2` 下发的 buvid 未经 `ExClimbWuzhi` 激活时服务端不信任，搜索只返回 `{"v_voucher": "..."}` 风控凭据。playurl 对信任度要求低，所以 M1 阶段没暴露这个问题。
2. **激活接口的 DTO 类型错误。** 声明为 `BiliResponse<String?>`，但接口返回 `data: {}`，kotlinx.serialization 抛 `$.data` 解析异常——激活调用其实**从未成功**。改为 `JsonElement`。
3. **风控响应被静默吞掉。** `SearchData` 所有字段都有默认值，`{"v_voucher":...}` 会被反序列化成一个空 `SearchData` 而非 null，原先的 null 检查拦不住。

**修复**：补上激活调用、修正 DTO 类型、给凭据加 `activated` 标记（未激活视为无效以强制重新种植）、空结果显式报错。

> 教训：**给 DTO 字段设默认值会让「结构不符」变成「静默空值」。** 风控响应与正常响应的结构差异因此被抹平，排查成本极高。

### 2. `derivedStateOf` 无 key 导致分页永不触发

```kotlin
// 错误写法
val shouldLoadMore by remember {          // ← 没有 key
    derivedStateOf { last >= state.items.size - 3 && state.items.isNotEmpty() }
}
```

`state` 是普通参数而非 `State`，`remember` 无 key 时 lambda 永久捕获首次组合的空列表，`isNotEmpty()` 恒为 false。

**修复**：`remember(itemCount)` 带 key。修复后连续下滑可加载到第 7 页。

### 3. 标题 HTML 实体二次转义

接口返回的标题形如 `&amp;quot;当音乐再次响起&amp;quot;`——先转义引号，又转义了 `&`。需要**解两遍**才能还原。已加单测锁定。

### 4. 点多 P 结果时错误地跳转播放页

原实现在 `onResultClick` 后无条件切 tab，导致点到多 P 视频时跳到空的播放页，看不到展开的分 P 列表。改为通过 `playbackStarted` 事件驱动跳转——**只有真正起播才跳**。

## 工具经验

**OkHttp 的 `addInterceptor` 看不到 Cookie 头。** Cookie 由 `BridgeInterceptor` 添加，运行在应用层拦截器之后。排查「cookie 有没有发出去」必须用 `addNetworkInterceptor`——我一度据此误判 CookieJar 失效。

**`adb shell input text` 只能输入 ASCII。** 测中文搜索得换关键词（用 `music` / `album` 等）或改用 CLI 脚本先行验证接口。
