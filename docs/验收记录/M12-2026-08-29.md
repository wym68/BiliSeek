## 2. M12-A 莫奈取色（模拟器视觉验证）

**设计**：系统莫奈（Android 12+ 动态取色，Theme.kt 既有行为不变）管全局配色；封面取色只作用于播放器局部背景。策略层为纯函数，与播放链路无耦合。

| # | 判据 | 结果 | 证据 |
| --- | --- | --- | --- |
| A-1 | 展开播放器背景随封面变化，换歌变色 | ✅ | 像素扫描：深色封面（千本樱）→ 亮色模式下背景呈暗色渐变（y=950:(120,119,122) → y=2300:(147,146,150)），平滑单调；亮色封面（MIKU，主色 (192,240,240)）→ 暗色模式下呈青色渐变（y=950:(58,69,73) → y=2300:(49,58,62)），与计算值吻合 |
| A-2 | 亮封面在暗色模式自动压暗（scrim），文字可读 | ✅ | logcat 实测决策值：`dominant=(192,240,240) dark=true → scrim=surface@0.6`；像素确认背景被压回表面色附近（文字区对比度达标） |
| A-3 | 无封面（纯音频）回落 M3 默认，不闪白 | ✅ | logcat：`dominant=null → top=bottom=surface, scrim=null`；单测 `无封面时回落默认表面色` 钉住 |
| A-4 | Android 12+ 全局仍跟随系统莫奈 | ✅ | Theme.kt 未动；亮/暗两套动态取色切换正常（uimode 切换验证） |

**验证中的一处坑（已定位，非缺陷）**：深色封面在暗色模式下背景与表面色仅差 2–3 单位（肉眼不可见）——这是「深色封面 + 暗色主题」的数学必然（主色与表面本就同亮度区间），不是取色失效；亮色模式下同一封面有明显渐变可证链路是通的。

**单测覆盖**（`AccentPolicyTest`，12 例）：无封面回落 / 渐变端点与收敛方向 / blend 端点与越界 / 亮封面暗模式压暗 / 暗封面暗模式不压暗 / 亮色模式任意封面不压暗 / 临界亮度边界 / 对比度公式对称性 / 点缀色对比不足回退 null / 点缀色正常给出 / 非 12+ 无系统莫奈时封面取色照常生效 / 暗色模式决策输出。

| # | 判据 | 结果 |

**全离线设计**：测试覆盖 `connection.offlineLookup` 指向拷贝到私有目录的测试资产（mp4 带音视频轨）。取流层 `offlineLookup` 回调在风控凭据（`awaitReady`）**之前**拦截（M9 §9.4 的拦截点）——播放完全不碰真实网络，模拟器搜索被服务端降权（-352/-412）影响不到这条链路。

**不需要生产代码测试缝**：`MainActivity` 的 `by viewModels()` 与测试里 `ViewModelProvider(activity)` 共享同一个 ViewModelStore，测试直接取同实例覆盖 `offlineLookup` 即可。计划稿里的 `connectionFactory` 缝因此未落地（更简、更稳）。

## 4. 与计划的偏差（均为实现层面的简化）

1. **`connectionFactory` 测试缝未落地**——VM 与 Activity 共享 ViewModelStore，测试直接取同实例覆盖 `offlineLookup`，零生产代码改动（见 §3.1）。
2. **莫奈取色不加设置开关**（计划已声明默认决策，用户无异议）——默认跟随系统与封面，无新增设置项。
3. 封面取色用 `androidx.palette:palette-ktx`（计划已声明，用户无异议）——官方小库，正是 BBPlayer `image-theme-colors` 的等价实现。
