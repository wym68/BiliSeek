### E-1 证据：下载链路与「已下载」分区

搜索结果长按 → 操作菜单 **五项**（加入歌单 / 下一首播放 / 复制链接 / 查看分 P / **下载**）→ 确认面板：

```
下载
  [标题]
  内容      ○ 只音频（m4a）   ○ 视频（mp4）
  保存位置  ○ 应用内  ○ 公共媒体库  ○ 自定义目录
  [取消]  [开始下载]
```

下载进行中：前台服务 `DownloadService` 启动（`ActivityManager: Background started FGS ... DownloadService ... code:PROC_STATE_TOP`），
通知栏出现进度。完成后音乐库页出现「**已下载 · 1 个 ›**」分区，点入列表：

```
已下载 · 1 个
Lofi Chill Music☔丨再留一晚丨深夜Lofi与雨夜氛围，助你深度专注
音频 · 应用内 · 156.5 MB        [播放] [删除]
```

数据库落库（`run-as` 内直接查）：

```
2|BV1cs8t6REjZ|41193244664|AUDIO|PRIVATE|DONE|file:///.../files/downloads/BV1cs8t6REjZ_41193244664.m4a|164108792
```

下载文件头部验证是完整 fMP4：`00000020 6674 7970 6973 6f35 …（ftyp iso5/iso6/mp41/dash）`。

### E-2 证据：飞行模式离线播放（★ 最硬判据）

`svc wifi disable && svc data disable` 后，从「已下载」点播放：


### E-14 证据：搜索筛选 + 页码归 1

搜索页新增两排筛选 chip（综合/最多播放/最新/最多弹幕 · 不限时长/10 分内/10–30 分/30–60 分/60 分+）。
点「10 分内」后请求参数：

```
search/type?search_type=video&keyword=lofi&page=1&page_size=20&duration=1&wts=…&w_rid=…
```

`duration=1` 进 WBI 签名（整表签名，无需额外处理）；切换时 `page=1`——页码归 1。
结果全部变成短时长（05:22 等）。

### E-15 证据：全屏一次返回即退出

看模式下点「全屏」→ overlay 出现（系统栏隐藏）→ **按一次返回键**：

```
▾ 正在播放 / Sad life lofi / 00:19 / 00:19 / 退回「听」…
```

一次返回回到展开态，没有先被系统吃掉第一次。`FullscreenPlayerOverlay` 内层
`BackHandler` 生效（Compose 内层优先于 AppShell 外层）。

### E-16 证据：Cookie 刷新公钥（⏸ 未验证）

公钥已**填入** `CookieRefresher.CORRESPOND_PUBLIC_KEY`，并给出字节级出处证据：
从线上 wasm `wasm_rsa_encrypt_bg.wasm`（当日抓取）中比对出模数（去掉前导 0 后逐字节一致），
且与 bilibili-API-collect 逆向报告的 JWK `n` 一致。新增单测 `真实公钥可解析且模数与线上 wasm 一致` /
`真实公钥加密输出为小写 hex 且长度等于模长`（1024 位密钥 → 256 hex 字符）。

**但端到端的「一次真实刷新」需要真人扫码登录后才能验证**（服务端对未登录请求的
`/correspond/1/{path}` 一律回 404，无法用无账号请求判定密钥对错）。按《功能优化篇》§2.4 口径：
**如实标注未验证**。若密钥有误，失败模式是刷新静默失败 + 周期性掉登录，与未填时等价；
日志会从 `NotConfigured` 变为 `Failed(...)`，可据此归因。

## 过程中修掉的三个真 bug（模拟器实测撞出）

1. **`NetworkOnMainThreadException`**：`DownloadService` 的 scope 是 `Main.immediate`，
   `processQueue` 里的阻塞式 OkHttp 跑在了主线程。改为 `processQueue` 内部
   `withContext(Dispatchers.IO)`。
2. **SAF 重下产生「xxx (1).m4a」**：`DocumentFile.createFile` 同名不覆盖。
   改为先 `findFile(fileName)?.delete()` 再建。
3. **MediaStore 重下产生重复条目**：同名直接 insert 会得到「xxx (1).mp4」。
   改为 insert 前按 `DISPLAY_NAME` 删掉本目录下的旧条目。

## 未验证与已知

- **E-16 真实刷新**：需真人账号（见上）。
- **下载中通知的「进度条」形态**：通知的 `setProgress` 路径与「已下载」列表的进度条
  均在本次模拟器验证中随任务推进观察到（列表内进度条在下载中持续更新并最终变红/变完成）。
- **Public/SAF 的重下替换**：语义为「替换我们上次下的同名文件」，SAF 与 MediaStore 两条路都已实测；
  若用户在所选目录里恰好有同名自有文件，会被一并替换——属可接受边界（文件名是
  `{bvid}_{cid}`，撞名概率极低）。
