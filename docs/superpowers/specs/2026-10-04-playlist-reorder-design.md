# 本地列表长按拖动排序：进入移动模式的提醒、其他行让位、边缘自动滚动

日期：2026-10-04
范围：`app` 的 `ui/LibraryScreen.kt`（`PlaylistDetail`）、`ui/PlaylistReorder.kt`（新增）、`data/ReorderPolicy.kt`。

## 背景（用户原话）

> 现在本地列表中长按上下然后拖动实现移动的功能不好用。长按后没有进入可移动模式时的提醒，可以通过视觉改动和马达振动提醒，然后移动的时候也没有插入的效果。想把一条插入到另外的中间比较困难。

## 现状与原因

- **没有进入提醒**：长按后那一行只变成浅灰底（`surfaceVariant`），几乎看不出来，也不震。
- **没有插入效果**：拖动时只有这一行跟着手指走，盖在别的行上，别的行不动，看不出会落在哪。
- **落点会偏**：落点在松手时按「位移 ÷ 行高」四舍五入算，行高按 72dp 算，没算 1dp 分割线，拖得越远越偏。
- **重复拖会乱**：拖动手势按「条目 id + 条数」建一次，里面记的是当时的下标和列表；排过一次序后条数不变，再拖同一条还用旧下标和旧列表算落点，可能落错位置。
- **拖不出屏幕**：拖到列表上下边缘不会自动滚动，屏幕外的位置去不了。

## 方案（用户在效果图里选了 C：浮起卡片 + 拖动手柄）

效果图：`.superpowers/brainstorm/1751126-1791122364/content/reorder-style.html`（生成脚本 `/tmp/biliseek-fonts/build_reorder_mock.py`）。

1. **拿起来**：
   - 长按满时间震一下（`HapticFeedbackType.LongPress`）。
   - 那一行变成左右各缩进 8dp 的圆角（12dp）卡片：浅色用最白的一档、深色高一档（同 `AppToast`），阴影 8dp，放大到 1.03 倍。
   - 右侧三点换成主色的拖动手柄，这一行下面的分割线隐藏。拿起和放下都有约 150ms 的过渡。
2. **拖动**：
   - 被拖的那一行跟着手指走。它的中线越过别的行时，本地顺序挪一格，别的行滑开让位（`Modifier.animateItem()`，只动位置，不加淡入淡出），空出来的格子就是落点。
   - 每挪一格轻震一下（`HapticFeedbackType.SegmentTick`）。
   - 几何按 `LazyListState.layoutInfo` 实际测的位置算，不再按固定行高推，分割线也算在内。
3. **边缘自动滚动**：被拖那一行进入列表上下 48dp 边缘区时列表自动滚动，越靠边越快，最快约 800dp/秒；滚动时照样让位、挪格。
4. **松手**：
   - 这一行从手指处滑进空位；按「最初位置 → 最终位置」用 `reorderNeighbors` 取两侧 `sortKey` 写一次库，位置没变不写。
   - 写库前界面先按本地顺序显示，数据库回来同样的顺序后再切回库里的列表，不闪。
   - 手势被打断时恢复原顺序。
5. **代码**：
   - 状态与手势收进 `ui/PlaylistReorder.kt` 的 `PlaylistReorderState`。手势回调读的都是最新的列表和回调，不再留着旧下标。
   - 纯函数放在 `data/ReorderPolicy.kt`（有单测）：`moved`（列表里挪一项）、`reorderSwapTarget`（中线落在哪一行上）、`autoScrollSpeed`（边缘滚动速度）。
   - 不再用的 `reorderTargetIndex`（按固定行高推落点）删除。

## 不做

- 右滑删除、三点菜单、条目点击不变；提示文字「长按拖动排序，右滑删除」不变。
- 其他列表（播放队列、收藏夹）不加拖动排序。

## 风险

- 震动跟随系统触感开关。
- 拖动第一屏最上面那一行时，懒加载列表默认会跟着第一项滚动；按官方示例在挪格时用 `requestScrollToItem` 钉住当前滚动位置。真机上要看拖第一行时会不会跳。

## 测试与验证

- 先写 `ReorderPolicyTest` 新用例（列表挪一项、中线命中、边缘速度）并确认编译失败，再实现；删掉 `reorderTargetIndex` 的用例。
- 拖动手势与动画没有 UI 测试（列表页参数很多、手势时序难稳定），由用户在真机上验证。
- `./gradlew test assembleDebug :app:compileDebugAndroidTestKotlin`；不装机，等用户开口。
