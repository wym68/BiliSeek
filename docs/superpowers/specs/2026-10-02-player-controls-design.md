# 播放页：控制行、听 / 看开关、倍速与定时、播放模式提示、简介弹窗

日期：2026-10-02
范围：`app` 模块播放页（`ui/PlayerScreen.kt`、`ui/PlayerControls.kt`、新增 `ui/PlayerSwitchRow.kt`、`ui/WatchTvIcon.kt`、`ui/VideoDescription.kt`、`ui/PlayerSheets.kt`）、新增纯函数 `ui/PlayModePolicy.kt`、`ui/SleepTimerChipPolicy.kt`，以及 `AppViewModel.cyclePlayMode()` 与 `MainActivity` 的提示。
承接 `docs/05` §13 里早先「播放页控制行并入底栏 / 简介区」的两次改动（本次是对它们的重做）。

## 背景

用户在播放页截图上反馈了五件事：

1. 控制按钮没有均匀分布，大小要重新设计；
2. 「看 / 退回听」按钮的外观和文字不好，要重新设计，包括切换之后的样子；
3. 点左侧播放模式按钮会切换，但没有浮框提示；并问四种模式分别是什么意思；
4. 简介太占地方：只把「简介」两个字做成链接，点开弹窗看内容；没有内容时「简介」用普通文字色、不加链接和弹窗，有内容时用链接的蓝色；控制按钮因此上提；
5. （看效果图时补充）倍速现在藏在三点菜单里，但经常用，要直接放在播放页；同时要求定时关闭也一起放出来；「看」的图标换成小电视，现在的播放箭头没有「看」的意思。

用户在浏览器效果图里的选择：开关放**控制行下方**；倍速、定时放**开关两侧并排**（一排三个）；「看」用小电视图标。

## 现状的问题

- **间距不均**：播放键在正中，左边 2 个按钮、右边 3 个按钮各在半边里均分，相邻按钮中心距依次约 64 · 74 · 59 · 48 · 48dp。六个按钮不可能既以播放键为轴对称、又放得下，所以把「看 / 退回听」挪出这一行。
- **大小不一**：上一首 / 下一首 30dp 图标、播放模式 24dp、播放键 64dp、右边的开关是 20dp 图标叠一行小字。
- **「看 / 退回听」**：听的时候写「看」、看的时候写「退回听」——一个按状态、一个按动作；无论哪个状态都用强调色，看不出当前是听还是看。
- **播放模式四种**：顺序播放 / 列表循环 / 单曲循环 / 随机播放（点一下按这个顺序循环）。**顺序播放和列表循环用同一个循环图标**，只差灰色和蓝色，很难分清。
- **简介**占约 150dp 高度，把进度条和控制行一直挤在屏幕底部。

## 方案

### 1. 控制行：5 个按钮等间距，播放键在正中

一行 `SpaceEvenly`：播放模式 · 上一首 · 播放 · 下一首 · 播放列表。左右两组宽度对称（48 / 56 / 72 / 56 / 48dp），所以播放键正好在屏幕中线，间距一致。

| 按钮 | 点击区 | 图标 |
| --- | --- | --- |
| 播放模式、播放列表 | 48dp | 26dp |
| 上一首、下一首 | 56dp | 34dp |
| 播放 / 暂停 | 72dp | 40dp |

360dp 宽的屏幕（内容宽 328dp，按钮总宽 280dp）间距约 8dp，仍然放得下。上一首 / 下一首不可用时仍是半透明且不响应点击（`SkipButton` 不变）。

### 2. 播放模式：四个图标 + 切换提示

| 模式 | 含义 | 图标 | 颜色 |
| --- | --- | --- | --- |
| 顺序播放 | 按列表顺序播，播完最后一首停止 | 向右箭头（`ArrowRightAlt`） | 灰（`onSurfaceVariant`） |
| 列表循环 | 播完最后一首回到第一首 | 循环（`Repeat`） | 主色 |
| 单曲循环 | 一直重复当前这一首 | 循环带 1（`RepeatOne`） | 主色 |
| 随机播放 | 在列表里随机挑下一首 | 交叉箭头（`Shuffle`） | 主色 |

- 解决「顺序」与「列表循环」同图标的问题：顺序播放是平的灰箭头，其余三种各有各的图标。
- 点击切到下一种（顺序 → 列表循环 → 单曲循环 → 随机 → 顺序，与现在一致）；**每次切换弹一条系统 Toast，只写模式名**（「单曲循环」），连点只显示最新一条（沿用 `MainActivity.showReplacingToast`，不走会排队的全局消息管道）。
- 按钮的无障碍描述从「播放模式」改成「播放模式：单曲循环」（带当前模式）。
- 纯函数 `PlayModePolicy.kt`：`nextPlayMode(current)`（循环顺序）、`playModeLabel(mode)`（四个名字）。设置页「列表播放模式」的四个名字改为引用 `playModeLabel`，避免两处各写一份。`AppViewModel.cyclePlayMode()` 改为返回新模式，`MainActivity` 拿它弹提示。

### 3. 听 | 看开关（控制行正下方）

- 分段胶囊：外框 1dp 描边（`outlineVariant`），内边距 4dp（描边内侧留 3dp 空隙）、整体高 40dp；两段「听」「看」，每段最小宽 60dp、高 32dp、左右内边距 10dp，图标 18dp + 6dp 间距 + 16sp 文字（`bodyLarge`），整个胶囊宽约 130dp。
- **选中的一段**填主色、文字图标用 `onPrimary`、文字加粗；**未选中的**透明底、`onSurfaceVariant`。始终看得出现在是听还是看，切换后换到另一段，没有「退回」这种文字。
- 图标：「听」`Headphones`；「看」**小电视**（带两根天线的电视机身、挖出屏幕），自绘矢量 `WatchTvIcon`（Material 自带的 `Tv` 没有天线，`LiveTv` 里是播放三角——正是要摆脱的意思）。
- 点未选中的一段 = 切换（走原来的 `onPresentationChange`，听 → `INLINE`、看 → `NONE`）；点已选中的一段不做事。切换时仍有「确认」触感。
- 语义：整个胶囊 `selectableGroup`，每段 `selectable(role = RadioButton)`。

### 4. 倍速与定时胶囊（开关两侧）

下面一排是「倍速 · 听 | 看 · 定时」：开关始终在正中，和上面的播放键对齐；两边的胶囊紧贴开关（间距 8dp），左右对称。

- **倍速胶囊**（左）：仪表盘图标 + 文字。正常速度（1×）写「倍速」，灰色描边；调过之后变主色（12% 主色底、50% 主色描边）、写当前倍速（`1.5×`）。文字沿用全屏底栏按钮的 `speedButtonLabel`。点它弹出**现有的倍速弹层**（0.5 / 0.75 / 1 / 1.25 / 1.5 / 2 / 3，选完生效并收起）。
- **定时胶囊**（右）：计时器图标 + 文字。没设定时写「定时」（灰色）；设了之后变主色、写剩余时间（`28:40`，超过一小时 `1:00:00`）；选的是「播完当前」写「播完当前」。点它弹出**现有的定时弹层**（15 / 30 / 60 分钟、播完当前，已设定时可取消）。文字由纯函数 `sleepTimerChipLabel(remainingMs, endOfTrack)` 给出。
- 胶囊高 32dp、左右内边距 10dp，点击区扩到 48dp（`minimumInteractiveComponentSize`）；文字用 `labelMedium`，单行。胶囊占开关两侧各自一半的剩余宽度：393dp 宽的屏幕每侧约 115dp、360dp 宽约 99dp，扣掉 8dp 间距后都放得下最长的 `1:00:00` 和「播完当前」（88dp）；再窄或系统字体放大时文字省略。
- 无障碍：设了倍速 / 定时之后，整个胶囊的描述带上含义（「倍速 1.5×」「定时关闭 剩余 28:40」）；没设时文字本身就够清楚，不另加描述。
- **三点菜单里原有的倍速、定时关闭入口不动**（那里还有下载、音质等；全屏播放也有自己的入口）。倍速 / 定时两个弹层抽成 `PlayerSpeedSheet` / `PlayerTimerSheet` 由菜单和播放页共用。

### 5. 简介：只留一行，点开弹窗

页面上的简介行：左边「简介」，右边「播放 676.1 万 · 1月16日」（统计行与现在一致）。

- **有内容**（`VideoDescriptionPolicy.shouldShow(desc)`：非空白且不是单个「-」）：「简介」用链接色（与页面里别的链接同色），可点，点开底部弹层；
- **没有内容**：「简介」用普通文字色，不可点、没有弹窗；
- 简介和统计都没有（本地文件、详情还没加载）时整行不显示（与现在一致，也避免详情加载前先闪一下灰色「简介」）。
- 点击区至少 40dp 高（文字本身只有一行 20dp）。

弹层用 `SettingsSheet`（与加入列表 / 下载同款）：标题「简介」，正文可上下滑、可长按选择复制。时间点和链接照常可点——点时间点跳到那里播放、点视频号在应用里打开、点其他网址交给浏览器——**点了之后弹层自动收起**，这样能直接看到播放跳转。换视频（切歌、自动下一首）时弹层跟着收起。

原来的 `VideoDescriptionSection`（默认 4 行 +「展开全部 / 收起」）整个换成「简介行 + 简介弹层」，`VideoDescriptionPolicy.COLLAPSED_LINES` 随之没人用，一并删除。

### 6. 控制行上提

简介正文不再占高度，中段（标题 / 互动栏 / 简介行）从「撑满剩余高度」改成「按内容高度、放不下时仍可滑动」（`weight(1f, fill = false)`）。于是进度条、控制行、开关行紧跟在简介行下面，**屏幕下方留出空白**（原来简介占的位置），不再被挤到屏幕底部。小屏幕上中段会被压矮，靠滑动查看，不会出错。

## 不做

- 不动三点菜单里的倍速、定时关闭入口；不动全屏播放的任何控件。
- 不做「点倍速胶囊直接循环档位」：用现有弹层，精确、与菜单一致。
- 不改 `PlayerControlBar`（全屏控制层在用）；它里面一个没人用的「看 / 退回听」分支（`showModeSwitch`，唯一调用方传的是 false）也先留着，只在报告里提。
- 不为听 / 看开关加切换动画（切换是异步的，选中态跟着播放器状态走）。

## 风险

- 窄屏（≤ 360dp 宽）或系统字体放大时，一排三个控件可能挤；胶囊单行省略兜底，开关固定宽度不变。
- 小电视图标是按路径手画的，真机上看是否像「小电视」、与「听」的耳机图标视觉大小是否匹配，需要用户看一眼；不满意改一个文件（`WatchTvIcon.kt`）。
- 控制行上提后，高屏手机下方空白较多（是用户要的）；若觉得空，可再调中段与控制行之间的留白。
- 界面接线没有单测，仪器化测试（`PlayerUiTest`）只做了编译核对、没在设备上跑。
