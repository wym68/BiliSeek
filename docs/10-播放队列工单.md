# 播放队列工单：两层队列 + 列表来源 + 删除与撤销

本篇记录播放队列在「点击播放会不会冲掉队列」这件事上的规则和实现。代码里凡是注释写 `docs/10` 的地方，规则都以本篇为准。

## 1. 背景

改动前，点任何视频都会整队替换：`PlayerConnection.load()` 里执行 `queue = listOf(request)`，`playQueue()` 也是整队替换。用户用「加入队列」「下一首播放」攒好的曲目点一下就没了，也没有撤销。

各列表的行为也不统一：
- 本地歌单：整张替换队列。
- 合集、稍后再看、收藏夹：只把点的那一个视频放进队列，播完就停。

队列面板的「清空队列」按钮放在列表下方，`LazyColumn(Modifier.fillMaxSize())` 占满了高度，队列一长，按钮就被挤出屏幕。

## 2. 规则

| 场景 | 队列行为 |
|---|---|
| 「加入队列」「下一首播放」 | 条目标记为**固定**，点击播放永远不会删掉它 |
| 本地歌单、合集、稍后再看里点一项 | **整个列表**作为**临时块**进入队列，从点的那一项开始播 |
| 收藏夹里点一项 | 只把这一个视频作为临时块放进队列（多 P 视频就是全部分 P） |
| 搜索、历史、下载、动态、UP 投稿、消息里点一项 | 只把这一个视频作为临时块放进队列（多 P 展开为全部分 P，同改动前） |
| 每次点击 | 删掉旧的临时条目，固定条目保留 |
| 固定条目的位置 | 排在**整个临时块之后**：列表播完才轮到固定条目 |
| 已播放过的固定条目 | 留在队列里（「上一首」还能回去），直到用户点「清空队列」 |
| 合集这类远程分页列表 | 先放入已加载的条目；播到离临时块末尾不到 2 项时，自动请求下一页并接在块尾（每次只请求一页） |
| 列表里的多 P 视频 | 进队列时只占一项；**轮到它播放时**才取分 P，是多 P 就原地展开 |
| 一键清空队列 | 标题行固定显示「清空队列」。清掉除正在播放那一项以外的全部条目（固定和临时都清），并停止续页；正在播的保留，否则播放会被打断 |
| 右滑删除单条 | 队列面板里向右滑动某一行即删除该条目；正在播放的那一行不能滑动 |
| 右滑提示 | 标题下常驻一行小字「右滑删除单条」；第一次打开面板时，第一条可删除的行自动向右滑出一段再弹回，演示一次，之后不再演示 |
| 清空队列；右滑删除；点击时替换掉了 ≥2 个临时条目 | 弹出 Snackbar「撤销」 |

示例：固定条目 `[B][C]`，在合集 `[v1][v2][v3][v4]` 里点 v2，队列变为 `[v2 正在播][v3][v4][B][C]`。v3 开始播放时，如果合集还有下一页，就把新的一页接在 v4 后面、B 前面。

不变式：**临时条目在队列里永远是连续的一段。** 点击整块插入，删除不破坏连续，分 P 原地展开。块尾计算、续页插入位置都依赖这一条。

## 3. 实现

### 3.1 纯函数（`core/player/.../internal/QueuePolicy.kt`，`QueuePolicyTest` 覆盖）

| 函数 | 作用 |
|---|---|
| `resolveQueueOnTap(pinned, current, newCount, startOffset)` | 点击播放的改写方案：保留的固定条目下标、新块插入位置、新下标、被替换掉的临时条目数 |
| `resolveTemporaryBlockEnd(pinned)` | 临时块末尾（开区间），续页插在这里 |
| `shouldLoadMoreContext(pinned, current)` | 正在播临时块、离块尾不到 2 项才续页 |
| `shouldOfferUndo(removedTemporary)` | 替换掉 ≥2 个临时条目才弹撤销 |
| `resolveRemoveAt(current, size, index)` | 删除单条后的新下标；删当前项返回 null（拒绝） |
| `resolveIndexAfterExpand(current, index, partCount)` | 原地展开分 P 后的新下标 |

### 3.2 `PlayerConnection`

- 队列从 `List<PlaybackRequest>` 换成私有的 `List<QueueEntry>`（请求 + `pinned` + `expandParts`）。对外的 `PlaybackState.queue` 不变，仍是请求列表。
- **点击入口**：`play(request)`（单个视频）和新增的 `playFromContext(items, startIndex, expandParts, loadMore)`（列表 / 多 P）都走 `applyTap`。旧的 `playQueue()` 删除。
- **固定条目**：`enqueueNext()`、`appendToQueue()` 生成固定条目。
- **播到时展开分 P**：注入 `partsExpander`。`load()` 取流前，如果当前条目带 `expandParts`，就取分 P 原地展开，改播 P1。标记先摘掉，只处理一次；失败按单 P 播。挂起回来核对 `trackGeneration`，用户这期间点了别的就作废。
- **续页**：`playFromContext` 的 `loadMore` 存为当前来源。`load()` 里满足 `shouldLoadMoreContext` 就请求一页，结果接在块尾。同一来源同时只有一个请求；返回空即不再续；失败不重试（风控 -352 下重试只会把限制拉长）。新的点击、清空队列都会换掉来源，迟到的结果直接丢弃。
- **删除与撤销**：`removeFromQueue(index)`、`clearQueue(): Boolean`，以及替换掉 ≥2 个临时条目的点击，在修改前写入撤销快照（队列、下标、播放进度、续页来源）。`undoQueueChange()` 恢复快照；当前条目变了就按原进度重新起播。之后用户的任何队列操作都会让快照作废。点击替换时通过 `onQueueReplaced` 回调通知 UI。
- **持久化**：`PersistedTrack` 新增 `pinned`（默认 `true`）和 `expandParts`（默认 `false`）。旧版本存下的队列恢复后全部算固定，不会被点击冲掉。续页来源是内存里的闭包，不落盘（遵守“远程数据不持久化”）：进程重启后临时块不再自动续页。

### 3.3 `app`

- `remote/PagedQueueSource.kt`：分页来源的续页，自己维护页码，不复用界面上的列表状态（播着合集 A 去翻合集 B，续页不能串到 B 上）。`PagedQueueSourceTest` 用假请求覆盖。
- `RemoteLibraryController`：`playSeriesArchive` 把已加载的合集内容 + `PagedQueueSource` 交给 `ListPlayer`；`playWatchLaterItem` 把整张稍后再看交给 `ListPlayer`（接口本来就一次取回全部）；`playFavoriteTrack` 仍走 `playBvid`。
- `AppViewModel`：`playBvid` 的多 P 分支、`playPage`、`playPlaylist` 改用 `playFromContext`；注入 `partsExpander`（`repository.pages`）和 `onQueueReplaced`；新增 `queueUndo`、`removeFromQueue`、`undoQueueChange`，以及右滑演示标记（`SettingsStore.queueSwipeHintShown`）。
- `PlayerQueueSheet`：「清空队列」移到标题行；列表用 `weight(1f, fill = false)`；每行包一层右滑删除（自己用 `draggable` + `Animatable` 实现，首次演示和手势共用同一个偏移量）；面板里有自己的 `SnackbarHost`。
- `MainActivity` / `AppShell`：收集 `queueUndo`，面板开着时在面板里弹，关着时在 `AppShell` 的 Scaffold 里弹（位于迷你播放条上方）。点「撤销」调 `undoQueueChange()`。

## 4. 验证

自动化测试一律离线、用假数据，绝不访问 B 站：

- `./gradlew :core:player:test`：`QueuePolicyTest`（两层队列、续页判定、删除、展开）、`PersistedSessionTest`（新字段往返、旧会话默认值）。
- `./gradlew :app:testDebugUnitTest`：`PagedQueueSourceTest`。

真机验证（由人来做）：

1. 用「加入队列」加 B、C，在合集里点第 2 项：队列是合集剩下的部分，后面接 B、C；快播到末尾时自动接上下一页。
2. 稍后再看里点一个多 P 视频：轮到它时展开为全部分 P。
3. 收藏夹里点一项：只有它进队列，B、C 还在。
4. 本地歌单里连点两次不同的歌：不会丢掉 B、C；第二次点击出现「撤销」，点了能回到前一个状态。
5. 队列有 30 项以上：「清空队列」按钮可见；点了只剩正在播放的那一项，合集不再续页；「撤销」能恢复。
6. 打开队列面板：能看到「右滑删除单条」；第一次打开时第一条可删除的行演示一次滑动，之后不再演示。
7. 右滑删除一条非当前条目：条目消失、播放不受影响，面板内出现「撤销」且能恢复；正在播放的那一行滑不动。
8. 杀掉进程后恢复：固定标记仍然保留（点击播放不会冲掉之前加入的曲目）。
