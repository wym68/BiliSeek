# BiliSeek 发版清单（M10 起）

> 每次发版照此执行。**没有 mapping.txt 就不算一次发版。**

## 0. 版本口径（M10-C）

- `versionName` 与里程碑对齐：MVP=0.1.0，M9 完成=0.2.0，后续里程碑每完成一个 +0.1
- `versionCode` 每次发版 **+1**（单调递增，绝不回退），只在发版提交上动
- 改法：`app/build.gradle.kts` → `defaultConfig`

## 1. 构建与归档

```bash
./gradlew test                       # 单元测试全绿
./gradlew :app:archiveReleaseArtifacts
# → 产出 releases/<versionName>/app-release.apk + mapping.txt
# 签名四键来自 local.properties（已 gitignore）或环境变量 BILISEEK_SIGNING_KEY_*
```

**或在 GitHub 上构建（推荐，产物自动归档）**：Actions → 「Build Release (draft)」→ Run workflow。
它会跑单测、构建带 R8 的签名 release、校验 mapping.txt 与签名、上传产物（保留 90 天），并生成 **草稿** Release
（tag `v<versionName>`，同名 tag 已存在时拒绝构建）。§2 的人工项做完后再在 Releases 页点 Publish。
首次使用前需在仓库 Secrets 配好四个签名 secret（名字见 `.github/workflows/build-release.yml` 头注释）。

验证签名：

```bash
$ANDROID_SDK/build-tools/<ver>/apksigner verify --print-certs \
  releases/<versionName>/app-release.apk
```

## 2. 必检项（缺一不可）

- [ ] **mapping.txt 已随 release 归档**（`releases/<versionName>/mapping.txt`）——用户报的崩溃堆栈没有它无从还原
- [ ] **源码入口是真实公开仓库**：设置页「关于」→「源码」指向 `https://github.com/wym68/BiliSeek`，发布前确认仓库已公开且含 `LICENSE`（GPLv3）+ `NOTICE`
- [ ] **release 包（开着 R8）在模拟器跑通 Part A 核心链路**（验收记录 M10 的 F-1~F-6）
- [ ] 签名密钥有备份（`~/.keystores/` 的 jks + 口令）：**丢失 = 永远无法覆盖升级**

## 3. 崩溃堆栈还原

用户报 `at jg.c(...)` 这类混淆堆栈时：

```bash
$ANDROID_SDK/cmdline-tools/latest/bin/retrace \
  releases/<versionName>/mapping.txt stack.txt
```

## 4. 密钥管理

- keystore：`~/.keystores/biliseek-release.jks`（权限 600，仓库外）
- 口令：`~/.keystores/biliseek-release.pass` + local.properties（双份，均不入库）
- `.gitignore` 已强制忽略 `*.jks` / `*.keystore` / `*.pass`
- 泄漏即作废：换新 keystore = 老用户无法覆盖安装，尽量不发生
