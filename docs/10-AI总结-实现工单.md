# BiliSeek 实现工单 · AI 总结（音视频 → Markdown）

> 状态：**待开工**（本文只是设计工单，未落任何代码）。
> 目标：用户自配 AI 服务，对一条视频（的某一 P）生成结构化 Markdown 总结；时间戳可点跳播。能力做成独立模块 `:core:ai`，后续其他入口（本地文件、合集批量、问答）直接复用。
> 前置：`AuthGate` / `WbiSigner` / `RequestThrottle` / `RiskCooldown`（Phase B 已落地）、`DownloadManager` 取流与 `DownloadService` 前台服务写法、`PlayerConnection.play(startPositionOverride)` / `seekTo()`。
> 关联：《架构设计篇》（模块边界、Service 承载长任务）、`CLAUDE.md`（Policy 纯函数、公开 API 克制、不持久化远端数据）、`AGENTS.md`（自动化不得联网）。
> **诚实红线**：
> 1. 自动化测试**既不打 B 站，也不打任何 AI 服务**（后者花钱、且 Key 不进 CI）。全部走 `MockWebServer` + 本地 fixture。
> 2. 第三方服务的行为（MiniMax 思考内容格式、各家转写是否支持 `verbose_json`、时长/体积上限、Token Plan 是否含转写额度）在拿到真机抓包前一律标「未验证」，不写成通过。

## 0. 背景与已定决策

需求来自讨论（2026-09-29）。参考了 BiliNote（MIT，字幕优先 + ASR 兜底 + map-reduce + 断点续做）、BibiGPT-v1（GPL-3.0，时间戳提示词、字幕压缩）、bilibili-subtitle（MIT，按 UP 主章节分段）。三者许可证均与本项目 GPLv3 兼容，但都非 Kotlin，**只借思路、不搬代码**。

| 维度 | 决策 |
|------|------|
| 模块 | 新建 `:core:ai`，**不依赖** `:core:network` / `:core:player`，不含任何 B 站概念；B 站接线在 `:app` |
| 提供商 | **可扩展的 Provider 架构**（§3）。v1 实现 OpenAI 兼容协议；预设：MiniMax 国内、MiniMax 国际、自定义（OpenAI 兼容）。模型名用户自填、无默认。Kimi Code 会员 Key 条款禁止编程工具以外使用，**不做预设** |
| 转写 | 独立一套配置（Whisper 兼容 `/v1/audio/transcriptions`），优先 `verbose_json`，不支持时降级纯文本 + 切片起点估时 |
| 内容来源 | B 站字幕优先（人工中文 > AI 中文 > 任意中文 > 首条）+ 同接口的 UP 主章节 `view_points`；无字幕走转写；有字幕但未登录拿不到 → 提示登录或选择改用转写 |
| 长文本 | 章节优先分块 → 按体积分块 → 超长单段二分；每块总结 → 合并（只合并去重、不编造、保留时间戳）；每块落 checkpoint 可续做 |
| 推理模型 | 剥离 `<think>…</think>` 与 `reasoning_content`，md 只留正文 |
| 入口 | 播放页 `VideoActionBar` 新增「总结」；所有 `ActionListSheet` 三点菜单 + 动态长按菜单加「AI 总结」 |
| 启动 | 已有总结 → 直接开阅读页（可「重新生成」）；生成中 → 开阅读页看进度；没有 → 风格选择弹窗（默认上次风格，标明走字幕/转写） |
| 多 P | 播放页 = 当前 P；列表入口 → 复用挑 P 页（多选，每个选中的 P 各排一个任务）；每 P 一份 |
| 风格 | 预设「精简 / 详细笔记 / 时间戳大纲」+ 自定义提示词 |
| 执行 | 前台服务（`dataSync`）+ 通知进度；任务串行排队 |
| 展示 | 引入成熟 Markdown 渲染库；流式实时显示；时间戳点击跳播 |
| 存储 | App 私有目录存 md + 原文（字幕/转写），Room 存索引；分享 / 另存导出（SAF） |
| 流量 | 转写（下载 + 上传音频）在计量网络下先确认并显示预估流量；字幕路径不拦 |
| 凭据 | API Key 用 Android Keystore（AES-GCM）加密后存 DataStore，**不进日志、不进 `AppSettings`** |

## 3. Provider 架构（可扩展）

**核心思路**：把「一家 AI 服务」拆成 **协议（怎么说话）** × **预设（在哪、叫什么、有何怪癖）** 两层。

- 加一家**已支持协议**的服务（例如 Kimi 开放平台、DeepSeek、通义、SiliconFlow）= **只加一条预设数据**，零代码逻辑。
- 加一种**新协议**（Anthropic Messages、Gemini、MiniMax 专有转写）= 实现一个 `ChatClient` / `TranscriptionClient` 适配器 + 在 `ProviderFactory` 注册一行 + 加预设。上层 `Summarizer`、UI、存储全部不动。

### 3.1 协议与能力

```kotlin
package com.biliseek.core.ai.provider

/** 线协议。新增协议 = 新增枚举值 + 适配器 + ProviderFactory 一行。 */
enum class ChatProtocol { OPENAI_COMPAT /*, ANTHROPIC, GEMINI — 预留 */ }
enum class TranscriptionProtocol { OPENAI_WHISPER_COMPAT /*, MINIMAX_STT — 预留 */ }

/** 推理模型的「思考内容」长在哪。决定 ReasoningStripPolicy 怎么剥。 */
enum class ReasoningFormat { NONE, THINK_TAG_IN_CONTENT, SEPARATE_FIELD, AUTO }

/** 一家服务在某协议下的已知怪癖。全部有保守默认值，预设只覆盖差异。 */
data class ChatCapabilities(
    val streaming: Boolean = true,
    val reasoningFormat: ReasoningFormat = ReasoningFormat.AUTO,
    /** 部分推理模型拒收 temperature；为 false 时请求里不带。 */
    val acceptsTemperature: Boolean = true,
    /** 单次请求正文字节上限（保守估计，用于 ChunkPolicy）。 */
    val maxRequestBytes: Int = 96 * 1024,
    /** 额外固定请求参数（如某家需要的开关），原样并入 body。 */
    val extraBody: Map<String, kotlinx.serialization.json.JsonElement> = emptyMap(),
)

data class TranscriptionCapabilities(
    val verboseJson: Boolean = true,          // 不确定时先试，失败降级（§AI-7）
    val maxAudioSeconds: Int = 600,
    val maxAudioBytes: Long = 24L * 1024 * 1024,
)
```

### 3.2 预设目录

```kotlin

data class ProviderPreset(
    val id: String,                 // 稳定 id，落库用；改名不改 id
    val displayName: String,
    val baseUrl: String,            // 自定义预设为空，由用户填

    val transcriptionCapabilities: TranscriptionCapabilities = TranscriptionCapabilities(),

object ProviderCatalog {
    val chat: List<ProviderPreset>          // minimax_cn, minimax_global, custom_openai
    val transcription: List<ProviderPreset> // custom_whisper（+ 实现时核对后加入的常见预设）

```

v1 预设（**baseUrl 与能力值实现时逐一以官方文档核对，未核对的标 TODO**）：

| id | 用途 | baseUrl | 备注 |
|----|------|---------|------|
| `minimax_cn` | Chat | `https://api.minimaxi.com/v1` | 国内版 Key 只能打国内域名 |
| `minimax_global` | Chat | `https://api.minimax.io/v1` | 国际版 Key 只能打国际域名 |
| `custom_openai` | Chat | 用户填 | 任意 OpenAI 兼容服务（Kimi 开放平台、DeepSeek、通义、Ollama…） |
| `custom_whisper` | 转写 | 用户填 | 任意 `/v1/audio/transcriptions` 兼容服务 |

MiniMax 的 `reasoningFormat` 先按 `AUTO`（两种都剥）；是否用请求参数让它把思考拆到独立字段，**真机核对后**再写进 `extraBody`。

### 3.6 网络隔离（硬约束）

`:core:ai` 使用**自己的 `OkHttpClient`**，由 `:app` 构造时从空白 builder 起步：**无 CookieJar、无 B 站拦截器、无 B 站 UA/Referer**。绝不能把 B 站 Cookie（SESSDATA）带给第三方 AI 主机。日志拦截器（若开）必须对 `Authorization` 头打码。此约束写成一条测试：`AiHttpClientTest` 断言发往 MockWebServer 的请求不含 `Cookie` 头。

### AI-1 — Provider 与 OpenAI 兼容 Chat

`OpenAiChatClient`：`POST {baseUrl}/chat/completions`，`Authorization: Bearer`，body `{model, messages, stream, temperature?}` + `extraBody`。

- **`SseParser`**（纯函数）：按行解析 `data:`，忽略注释行/心跳，`[DONE]` 结束；兼容 `\r\n`、跨 chunk 断行、单事件多 `data:` 行。不引入 `okhttp-sse`，自写 ~50 行以便单测。
- **`ReasoningStripPolicy`**（纯函数）：
  - `THINK_TAG_IN_CONTENT`：去掉 `<think>…</think>`；**流式场景**要处理标签跨增量切开（`<thi` + `nk>`）与未闭合（仍在思考中 → 暂不输出）。
  - `SEPARATE_FIELD`：只取 `delta.content`，丢弃 `delta.reasoning_content`。
  - `AUTO`：两者都做。
- **`AiErrorPolicy`**（纯函数）：`(httpCode, bodySnippet, exception) → AiError` + `shouldRetry(error, attempt)` + `backoffMs(attempt)`。规则：401/403 → Unauthorized 不重试；402 或 body 含 quota/insufficient/余额 → QuotaExceeded 不重试；400 + context/length/too long/token → ContextTooLong（交给 AI-2 缩块）；429 → RateLimited（尊重 `Retry-After`，最多 3 次）；5xx/超时 → 指数退避最多 3 次；400 + temperature → 去掉 temperature 重试 1 次（借鉴 BiliNote）。
- **「测试连接」**：发一条极短消息（`"ping"`，`max_tokens` 很小），只判断能否拿到 2xx + 可解析响应。**仅用户点击触发**。
- proguard：`-keep,includedescriptorclasses class com.biliseek.core.ai.**$$serializer { *; }` 及配套规则（照现有 DTO 段落）。
- 验证：`SseParserTest`、`ReasoningStripPolicyTest`（含跨增量切标签、未闭合、嵌套/多段、无标签）、`AiErrorPolicyTest`、`OpenAiChatClientTest`（MockWebServer：请求形状、非流式、流式拼接、错误映射、无 `Cookie` 头）。

### AI-2 — 总结流水线（`Summarizer`）

流程：`Transcript` → 压缩 → 分块 → 逐块总结（每块落 checkpoint）→（多块时）合并（流式）→ 规整 md。单块时直接流式出正文。

- **`TranscriptCompactPolicy`**：把逐句字幕合并成约 20~30 秒一行的 `[mm:ss] 文本`（借鉴 BibiGPT，减 token 且保留跳转精度）；超过 1 小时的视频用 `[h:mm:ss]`。去掉空行和纯符号行（「♪」「[音乐]」等）。
- **`ChunkPolicy`**：输入压缩后的行 + `chapters` + `maxRequestBytes`（扣除提示词开销）。有章节 → 按章节切，超长章节再按体积切；无章节 → 按体积贪心装箱；单行超限 → 二分切（借鉴 BiliNote `request_chunker`）。输出 `List<Chunk(startMs, endMs, chapterTitle?, text)>`。遇到 `AiError.ContextTooLong` 时以 `maxRequestBytes / 2` 重新分块（最多 2 次）。
- **`PromptPolicy`**：`基础提示词 + 风格片段 + 格式约束 (+ 自定义)`。基础部分包含：中文输出、专有名词保留原文、「字幕可能有错别字请改正」、去广告/寒暄、**不要用代码块包裹输出**、**编号标题用 `## 1. xxx` 不用 `1. **xxx**`**、时间戳一律 `[mm:ss]`。`Timing.CHUNK` 时改为「时间戳仅标到段落级」。分块总结与合并各一套模板；合并模板要求「只合并去重、不发明新内容、保留全部时间戳」。
- **`MarkdownPolicy`**：剥 ```` ```markdown ```` 外壳；时间戳格式归一（`12.4 -`、`(03:12)`、`【03:12】` → `[03:12]`）；丢弃超出视频时长的时间戳；拼 md 头部（标题、元信息、生成时间、模型、来源）。
- **Checkpoint**：`checkpointDir/checkpoint.json` = `{signature, partials[]}`；`signature` = hash(转写内容 + 风格 + 模型 + 分块参数)，签名不符即作废。全部完成后删除。
- 并发：分块总结**串行**（订阅额度有并发限制，且便于续做）。
- 验证：各 Policy 单测（压缩边界、章节切分、二分、提示词片段组合、md 归一的各种畸形输入）；`SummarizerTest`（MockWebServer 模拟 3 块 + 合并；中途失败后重跑只请求剩余块；ContextTooLong 触发缩块）。

### AI-3 — 设置与凭据

- **`KeystoreCipher`**：`AndroidKeyStore` 下生成 AES/GCM/NoPadding 密钥（别名 `biliseek_ai_key`，不要求用户认证）；密文 = IV + ciphertext，Base64 存 DataStore。解密失败（换机备份恢复、密钥被清）→ 视为未配置，提示重新填写，**不崩**。
- **`AiSettingsStore`**（独立 DataStore `biliseek_ai_settings`，不塞进 `AppSettings`）：`summaryEndpoint`、`transcriptionEndpoint`、`lastStyle`、`customPrompt`、`privacyNoticeAccepted`。写法照 `SettingsStore`（`StateFlow` + 同步 `current`）；Key 字段在 `StateFlow` 里只暴露「已配置 / 末 4 位」，明文只在构造请求时解密取用。
- 备份：当前 `allowBackup="true"` 且没有规则文件。新增 `fullBackupContent`（API ≤30）与 `dataExtractionRules`（API 31+）两份规则，**排除** `biliseek_ai_settings` 的 DataStore 文件（Keystore 密钥不随备份走，恢复后必然解不开）。
- **`AiSettingsScreen`**（设置页新入口「AI 总结」）：两段卡片「总结模型」「转写服务（可选）」，各含：预设下拉（MiniMax 国内 / MiniMax 国际 / 自定义）、Base URL、API Key（密码框，显示末 4 位）、模型名（必填）、「测试连接」按钮与结果；下方风格默认值与自定义提示词编辑。首次保存弹一次隐私说明：「字幕/音频将发送到你配置的第三方服务」。
- 验证：`KeystoreCipher` 走 instrumented 测试（JVM 无 AndroidKeyStore）；`AiSettingsStore` 序列化单测（加解密用假实现注入）；`AiSettingsScreenUiTest`（必填校验、预设切换带出 baseUrl）。

### AI-4 — B 站字幕来源

- `BiliApi` 新增：
  ```kotlin
  @GET("x/player/wbi/v2")
  suspend fun playerV2(@QueryMap params: Map<String, String>): BiliResponse<PlayerV2Data> // bvid, cid + WBI 签名（调用处 WbiSigner.sign）

  @GET
  suspend fun subtitleBody(@Url url: String): SubtitleBody   // subtitle_url，补 https: 前缀
  ```

- DTO（`SubtitleDto.kt`）：`PlayerV2Data{ subtitle: SubtitleInfo?, view_points: List<ViewPoint>? , need_login_subtitle: Boolean? }`、`SubtitleTrack{ id, lan, lan_doc, subtitle_url, ai_type, type }`、`ViewPoint{ from, to, content }`、`SubtitleBody{ body: List<SubtitleLine{from, to, content}> }`。字段一律可空/有默认，未知字段忽略。
- `BiliRepository.playerSubtitles(bvid, cid)` / `subtitleBody(url)`：`authGate.awaitReady()` → 过 `RiskCooldown` → `RequestThrottle` 走 `FEED` bucket（或新增 `SUBTITLE` bucket）；错误码按现有拦截链处理（`-352` 不重试）。
- **`SubtitlePickPolicy`**（`:app`，纯函数）：人工中文（`lan` 以 `zh` 开头且 `ai_type == 0`）> AI 中文（`ai-zh` 或 `ai_type != 0`）> 任意中文 > 首条；轨道存在但 `subtitle_url` 为空 → `NeedsLogin`。
- **`SummarySourcePolicy`**（`:app`，纯函数）：输入（字幕列表结果、是否登录、转写是否已配置、是否有本地已下载音频）→ `UseSubtitle(track)` / `NeedsLoginOrAsr` / `UseAsr(local|remote)` / `Unavailable(原因)`。风格弹窗据此显示「将使用：B 站字幕 / 音频转写（约 xx MB）」。
- **`BiliSubtitleSource`**：实现 `TranscriptSource`；`from/to` 秒 → ms；`view_points` → `Chapter`。
- 验证：DTO 解析用本地 fixture（人工字幕、AI 字幕、无字幕、未登录空 url、带/不带 view_points）；两个 Policy 单测。**真机**：登录/未登录各测一条有 AI 字幕的视频。

### AI-5 — 存储、任务与服务

- **Room 表 `ai_summary`**（DB v5 → v6，写 `MIGRATION_5_6`，更新 `MigrationTest`）：
  `id PK, bvid, cid, pageTitle, title, author, coverUrl, durationMs, style, sourceKind(SUBTITLE/ASR_REMOTE/ASR_LOCAL), presetId, model, status(QUEUED/RUNNING/DONE/FAILED), error, createdAt, updatedAt`；唯一索引 `(bvid, cid)`（重新生成即覆盖）。
- **文件布局**（`filesDir/ai_summary/{bvid}_{cid}/`）：`summary.md`、`transcript.json`（`Transcript` 序列化，重新生成直接复用，不再打 B 站/不再转写）、`checkpoint.json`（进行中）、`audio/`（转写临时切片，完成即删）。删除记录时整目录删除。
  > 与「不持久化远端数据」的关系：总结是用户主动触发生成的本地成果；`transcript.json` 作为其原料一并保存，**仅随用户的总结存在**，不做其他用途。
- **`SummaryManager`**（单例，照 `DownloadManager`）：`enqueue(SummaryJob)`、`regenerate(id, style)`、`cancel(id)`、`delete(id)`、`observe(bvid, cid): Flow<SummaryUiState>`（含流式正文）。任务串行；进程被杀后 RUNNING 行在下次启动时标为可续做（有 checkpoint 则从断点继续）。
- **`SummaryService`**：前台服务 `dataSync`，通知显示「获取字幕 / 转写 3/8 / 总结 2/5 / 生成中」，完成/失败通知可点开阅读页。队列空即 `stopSelf`。与 `DownloadService`、`PlaybackService` 生命周期互不绑定。
- **`SummaryNetworkPolicy`**（纯函数）：`(sourceKind, isMetered, estimatedBytes) → Proceed / ConfirmMetered(estimatedBytes)`。预估流量 = 音频下载体积（码率 × 时长）+ 上传体积（≈ 同量）。
- 验证：`SummaryNetworkPolicyTest`；`SummaryManager` 用假 `Summarizer` / 假 `TranscriptSource` 测状态机（排队、失败可见、重新生成复用 transcript、续做）；`MigrationTest` 5→6。

### AI-7 — 音频转写（无字幕兜底）

- **音频获取**：已下载（`DownloadEntity` DONE 且含音频）→ 直接用本地文件，**不请求 B 站**；否则用 `DownloadManager` 同一取流解析器（`resolveSource`）拿 `audioUrl`，以最低音质档下载到 `audio/`（媒体请求头照 `BiliNetwork.mediaRequestHeaders`，走 B 站那个 client，**不是** AI client）。
- **`AudioChunkPolicy`**（纯函数）：`(durationMs, bitrate, caps.maxAudioSeconds, caps.maxAudioBytes) → List<LongRange>`，取两者中更严的上限再留 10% 余量，片与片之间重叠 1~2 秒避免切断句子（合并时按时间去重）。
- **`AudioSplitter`**：`MediaExtractor` + `MediaMuxer` 按时间区间拷贝 AAC 帧到独立 m4a（不重编码，思路同 `DownloadManager` 的 mux）。
- **`OpenAiTranscriptionClient`**：`POST {baseUrl}/audio/transcriptions`（multipart：`file`、`model`、`response_format=verbose_json`、`language=zh` 可选）。返回无 `segments` 或 4xx 提示不支持 → 降级 `response_format=json`/`text`，该片整段作为一个 `TranscriptSegment(chunkStart, chunkEnd)`，`Transcript.timing = CHUNK`。降级结果记住在本次任务内，不每片都试错。
- **`AudioTranscriber`**（公开）：`suspend fun transcribe(file: File, config): Flow<TranscribeProgress>`，内部切片 → 逐片转写（串行）→ 偏移时间戳 → 去重拼接。可被将来的「本地文件总结」直接复用。
- 验证：`AudioChunkPolicyTest`；`OpenAiTranscriptionClientTest`（MockWebServer：verbose_json 解析、降级路径、错误映射）；`AudioSplitter` 用 `androidTest` + 一段内置短音频 fixture 验证切片时长。**真机**：一条 >30 分钟无字幕视频全流程；移动网络确认弹窗。

## 6. 风险与未决

1. **订阅条款**：Kimi Code 会员 Key 明文限制编程工具使用，不做预设；MiniMax Token Plan 未见此类限制，但以用户所购套餐的最新条款为准。设置页「去哪拿 Key」链接指向各家官方文档。
2. **MiniMax 转写额度**：Token Plan 是否覆盖 `speech_to_text`（`asr-1.0`，单次约 500 秒上限）**未确认**。确认后作为第一个「新协议」扩展案例（`TranscriptionProtocol.MINIMAX_STT`），验证 §3 扩展路径。
3. **思考内容形态漂移**：推理模型的输出格式各家不一且会变；集中在 `ReasoningStripPolicy` + 预设的 `reasoningFormat`，默认 `AUTO` 兜底。
4. **字幕接口变化**：`x/player/wbi/v2` 的 `subtitle` 字段在未登录时常返回空 url；AI 字幕可能延迟生成。DTO 全可空，失败走 `SummarySourcePolicy` 的明确分支，不静默。
5. **额度与并发**：订阅通常有 RPM / 并发限制；分块串行 + `RateLimited` 退避。超长视频（>3 小时）块数多、耗时长，UI 需显示预估块数。
6. **Markdown 渲染库兼容性**：版本与 Compose BOM、R8 的兼容需实测；有自写降级方案兜底。
7. **Keystore 可用性**：少数 ROM 的 Keystore 有 bug；解密失败一律按「未配置」处理并提示重填，不崩。
8. **音频切片精度**：AAC 按帧切，边界误差几十毫秒，对时间戳跳转无影响；重叠去重规则需单测覆盖。
