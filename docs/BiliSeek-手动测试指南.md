> 版本：v2.0（按测试方式重组）  
> 日期：2026-08-25  
> 适用：MVP（M0–M4）已完成的构建

本文分三条**互相独立、从头到尾可照做**的路径。选一条，从上往下执行即可，不需要在章节间跳转。


| 路径                | 适用场景    | 能测到什么                 |
| ----------------- | ------- | --------------------- |
| **Part A · 模拟器**  | 日常开发迭代  | 全部界面功能。测不了音频焦点、耳机、低端机 |

# Part A · 模拟器测试

## A1. 启动模拟器

```bash
cd ~/Documents/biliseek
emulator -avd BiliSeek_API35 &
```

等待开机完成（约 1–2 分钟）：

```bash
adb wait-for-device
adb shell getprop sys.boot_completed        # 返回 1 即就绪
```

## A2. 安装并清空旧数据

```bash
./gradlew installDebug
adb shell pm clear com.biliseek.debug       # 清数据，以便测首次启动
```

## A3. 打开日志窗口

**另开一个终端标签**，保持它一直开着：

```bash
adb logcat -c && adb logcat -s BiliSeekAuth:V BiliSeekPlayUrl:V BiliSeekPlayer:V
```

后面每一步都可以回头看这个窗口。日志的详细读法见 [附录 1](#附录-1日志查看详解)。

## A4. 界面功能测试

从这里开始**全部在模拟器界面上手动操作**，按顺序做。

### 步骤 1 — 首次启动

在启动器里点开 **BiliSeek**。


| 检查点  | 期望                                           |
| ---- | -------------------------------------------- |
| 首屏   | 显示「Seek and you shall hear.」+ 一行说明，**不是空白页** |
| 底部导航 | 「搜索 / 音乐库 / 设置」三个，**没有第四个**（无推荐页是产品身份）       |
| 通知权限 | Android 13+ 弹一次授权框，**选允许或拒绝都应能继续用**          |
| 日志窗口 | 出现「风控凭据种植完成」                                 |


### 步骤 2 — 搜索

顶部输入框输入 `music`（模拟器的 adb 输入法打不了中文，用界面软键盘可以打中文），点右侧「**搜索**」按钮。


| 检查点  | 期望                                    |
| ---- | ------------------------------------- |
| 结果头部 | 「约 N 个结果 · 第 1/M 页」                   |
| 结果条目 | 标题、UP 主、时长、播放量四项齐全                    |
| 标题文字 | **不应出现 `&amp;quot;` 或 `<em>` 这类残留符号** |


### 步骤 3 — 分页

在结果列表里往下滑到底。


| 检查点  | 期望                    |
| ---- | --------------------- |
| 自动加载 | 滑到底自动加载下一页，页码从 1/M 递增 |
| 内容   | 不重复、不跳号               |


### 步骤 4 — 点击播放

点任意一条结果。


| 检查点  | 期望                           |
| ---- | ---------------------------- |
| 播放器  | 自动展开，显示「正在播放」                |
| 视频区  | 显示「纯音频模式」（黑底白字）——**默认只听**    |
| 进度   | 秒数持续推进                       |
| 日志窗口 | 出现「MPD 组装完成：视频轨 N 条，音频轨 M 条」 |


### 步骤 5 — 一键切看（核心卖点）

点「**切「看」**」按钮。


| 检查点  | 期望                                        |
| ---- | ----------------------------------------- |
| 画面   | 3 秒内出现在原来的封面区，**页面不跳转**                   |
| 声音   | **不中断、不重复、进度不跳** ← 这才是关键                  |
| 自检卡片 | 播放页下方出现 `✓ 切换无缝：听 → 看`，buffering=0，seek=0 |


再点「**退回「听」**」，同样应看到 `✓ 切换无缝：看 → 听`。

> **只要出现 `✗` 就是失败**，说明切换时重新缓冲了或做了 seek。

### 步骤 6 — 跨页面播放不中断

MiniPlayer 在播放时，依次点底部「音乐库」→「设置」→「搜索」。


| 检查点        | 期望              |
| ---------- | --------------- |
| 声音         | **全程不中断**       |
| MiniPlayer | 始终显示在底部，标题和进度正常 |


### 步骤 7 — 多 P 视频

搜索 `album`，找一条专辑合集类的结果点进去。


| 检查点    | 期望                               |
| ------ | -------------------------------- |
| 搜索结果里  | 这个视频**只占一条**（折叠）                 |
| 点入后    | 展开成「BVxxxx · N 个分 P」列表，含「返回结果」按钮 |
| 分 P 条目 | 显示「P1 曲名」和时长                     |
| 点某个 P  | 播放该 P，**核对播放页时长与列表标注是否一致**       |


### 步骤 8 — 队列

接着上一步（播放某个分 P 后）。


| 检查点           | 期望                            |
| ------------- | ----------------------------- |
| 队列显示          | 播放页显示「队列 N / M」               |
| 点「下一首」        | 序号 +1，切到下一 P                  |
| 点「上一首」        | 序号 −1                         |
| 点播放模式按钮       | 循环切换：顺序 → 列表循环 → 单曲 → 随机 → 顺序 |
| 切到「单曲」后点「下一首」 | **应该换歌**，不是原地重播               |


### 步骤 9 — 本地歌单

底部点「音乐库」→「新建」，输入名字确定。


| 检查点            | 期望                   |
| -------------- | -------------------- |
| 新建后            | 歌单出现在列表，带「改名」「删除」    |
| 回搜索页**长按**任意结果 | 加入歌单（无歌单时自动建「我的歌单」）  |
| 点歌单进详情         | 显示「歌单名 · N 首」        |
| 点歌单里的条目        | **整个歌单作为队列播放**，从该条开始 |
| 改名 / 删除 / 移除   | 立即生效                 |


### 步骤 10 — 首页空状态

回搜索页，**把搜索框的字清空**。


| 检查点   | 期望                    |
| ----- | --------------------- |
| 搜索历史  | 出现关键词标签，每个带 ✕，右上有「清空」 |
| 最近播放  | 出现刚才播过的条目，带保存的进度      |
| 播放热力  | 出现小方块                 |
| 点历史标签 | 直接用该关键词搜索             |
| 点 ✕   | 删掉该条历史                |


> 这些全是**你自己的行为数据**，没有算法推荐——这是「没有推荐页」的产品身份。

### 步骤 11 — 后台与锁屏

播放中按 **Home 键**回桌面。


| 检查点     | 期望              |
| ------- | --------------- |
| 声音      | 继续播放            |
| 通知栏（下拉） | 出现媒体控制卡片，可暂停/继续 |


测锁屏前，模拟器需要先启用锁屏（AVD 默认关掉了）：

```bash
adb shell locksettings set-disabled false
```

然后按电源键锁屏、再唤醒（不解锁）。


| 检查点     | 期望            |
| ------- | ------------- |
| 锁屏界面    | 出现媒体控制卡片，标题正确 |
| 点卡片上的暂停 | 播放暂停          |


### 步骤 12 — 画中画

回到 App，切到**看模式**，然后按 Home 键。


| 检查点       | 期望                 |
| --------- | ------------------ |
| PiP 窗口    | 出现小窗，**里面有画面不是黑的** |
| 点小窗回到 App | 恢复内联看模式，画面连续       |


> PiP 黑屏是最典型的失败信号，说明「进后台回落音频」的判定误伤了 PiP。

### 步骤 13 — 续播

播放某条内容 **至少 30 秒**（位置每 5 秒回写一次），然后：

```bash
adb shell am force-stop com.biliseek.debug
adb shell am start -n com.biliseek.debug/com.biliseek.app.MainActivity
```


| 检查点      | 期望                    |
| -------- | --------------------- |
| 首页「最近播放」 | 显示刚才那条，带保存的秒数         |
| 点它       | **从保存的位置继续**，不是从 0 开始 |


> 一个刻意的行为：**如果上次听到距结尾不足 15 秒，会从头播**。这不是 bug——从 61 秒续播一首 62 秒的歌，用户看到的是「点了没反应」。

### 步骤 14 — 登录（需要你的 B 站账号）

底部「设置」→「生成二维码」，用手机 B 站 App 扫模拟器屏幕上的码。


| 阶段          | 期望                   |
| ----------- | -------------------- |
| 生成          | 显示二维码                |
| 手机扫描后（未确认）  | 界面变成「✓ 已扫描，请在手机上确认」  |
| 手机确认        | 「✓ 登录成功」，显示 UID      |
| 重启 App      | 仍是登录态                |
| 二维码放 3 分钟不管 | 变成「二维码已失效」，可重新生成     |
| 点「登出」       | 回到未登录，**但搜索和播放仍然可用** |


> **务必验证「登录非强制」**：全新安装后不登录，直接走完步骤 2–10。这是产品身份的一部分。

## A5. 模拟器特有场景

### 断网表现

```bash
# 断网
adb shell svc wifi disable && adb shell svc data disable
```


| 操作           | 期望                                     |
| ------------ | -------------------------------------- |
| 断网后杀掉 App 重开 | **界面完整、搜索框能输入**，不白屏不 ANR               |
| 断网时点播放       | 最终显示明确错误，**不是无限转圈** ⚠️ 当前要等约 85 秒，已知缺陷 |


```bash
# 恢复
adb shell svc wifi enable && adb shell svc data enable
```

恢复后再点一次播放，应能正常起播。

### 流量对比（验证「听模式省流量」）

⚠️ 模拟器的流量统计是**粗粒度轮询**，不强制刷新会一直读到 0：

```bash
adb shell dumpsys package com.biliseek.debug | grep appId      # 取 uid
adb shell dumpsys netstats --poll                              # 必须先这句
adb shell dumpsys netstats detail | grep -A 12 "uid=<你的uid>"
```

分别在听模式和看模式各播 1 分钟，对比 `rb=` 增量。预期是**量级差异**（实测约 160 倍）。

## A6. 收尾

```bash
adb emu kill        # 关闭模拟器
```

# Part B · 真机有线测试

**发版前必须走这条。** 音频焦点、耳机、真实解码器只有真机能验。

## B1. 手机端设置

1. 设置 → 关于手机 → 连续点「版本号」7 次 → 提示「已进入开发者模式」
2. 返回 → 系统 → 开发者选项 → 打开 **USB 调试**
3. 用数据线连接电脑（注意是数据线，不是只能充电的线）
4. 手机弹出「允许 USB 调试吗」→ 勾选「一律允许」→ 确定

## B2. 确认连接

```bash
adb devices
```

期望输出：

```
List of devices attached
<序列号>	device
```

**若显示 `unauthorized`**：手机上没点授权，重新拔插看弹窗。

**若显示 `no permissions`**：udev 规则缺失，在终端里执行

```bash
sudo apt install -y android-sdk-platform-tools-common
```

然后拔插一次数据线。

## B3. 安装

```bash
cd ~/Documents/biliseek
./gradlew installDebug
```

**若同时连着模拟器**会报错，需指定设备：

```bash
adb devices                    # 记下真机序列号
adb -s <序列号> install -r app/build/outputs/apk/debug/app-debug.apk
```

后续所有 adb 命令都加 `-s <序列号>`，或先关掉模拟器（`adb emu kill`）省事。

清数据以便测首次启动：

```bash
adb shell pm clear com.biliseek.debug
```

## B4. 打开日志窗口

另开一个终端标签：

```bash
adb logcat -c && adb logcat -s BiliSeekAuth:V BiliSeekPlayUrl:V BiliSeekPlayer:V
```

## B5. 界面功能测试

**在手机上手动操作，按顺序做。** 步骤与 Part A 的 A4 完全一致：


| 步骤  | 操作               | 关键检查点                                   |

| 1   | 打开 BiliSeek      | 首屏有 slogan 不空白；底部三个入口；日志出现「风控凭据种植完成」    |

## B6. 真机独有项

**这些是走这条路径的真正理由。**

### 步骤 16 — 有线耳机

播放中插入有线耳机。


| 操作        | 期望                                             |
| --------- | ---------------------------------------------- |
| 插入耳机      | 声音切到耳机                                         |
| **拔出耳机**  | **自动暂停**（`setHandleAudioBecomingNoisy`），不应外放继续 |
| 耳机线控暂停/播放 | 响应正确                                           |


### 步骤 17 — 蓝牙耳机

配对蓝牙耳机后播放。


| 操作          | 期望       |
| ----------- | -------- |
| 耳机上的暂停/继续   | 响应正确     |
| 耳机上的上一首/下一首 | 队列序号正确变化 |
| 断开蓝牙        | 自动暂停     |


### 步骤 18 — 音频焦点


| 操作                | 期望                   |
| ----------------- | -------------------- |
| 播放中来一通电话          | 自动暂停；挂断后可继续          |
| 播放中打开另一个音乐 App 播放 | BiliSeek 让出焦点并暂停     |
| 播放中收到微信语音消息       | 音量短暂降低（duck）或暂停，之后恢复 |


### 步骤 19 — 长时间稳定性

连续播放 **30 分钟以上**，期间频繁切页、切听/看、进出后台。

```bash
# 每隔几分钟采一次
adb shell dumpsys meminfo com.biliseek.debug | grep "TOTAL PSS"
```


| 检查点 | 期望                                                    |
| --- | ----------------------------------------------------- |
| 内存  | 趋于平稳；**持续单调增长**才是泄漏信号（短期波动正常）                         |
| 崩溃  | `adb logcat -d -s AndroidRuntime:E | grep FATAL` 应无输出 |
| 播放  | 全程不中断                                                 |


### 步骤 20 — 流量对比

真机上直接看系统统计，比 adb 简单：

**设置 → 网络和互联网 → 流量使用 → BiliSeek**

分别在听模式和看模式各播 5 分钟，对比消耗。预期是量级差异。

### 步骤 21 — Hi-Res（需大会员账号）

登录大会员账号，播放支持 Hi-Res 的视频。

⚠️ **部分设备的系统 FLAC 解码器只分配 32 KiB 输入缓冲**，而 B 站 Hi-Res 单帧可能超过，会崩溃。**这个坑只在真机上撞得到。**

```bash
adb logcat -s BiliSeekPlayer:V | grep -iE "flac|InsufficientCapacity"
```

### 步骤 22 — 低端机（如有）

找一台 2–4 GB 内存的老机器重复步骤 1–14。


| 检查点   | 期望                               |
| ----- | -------------------------------- |
| 滚动流畅度 | 不卡顿                              |
| 模糊与动效 | 应自动降级 ⚠️ **此功能尚未移植**，当前会与旗舰机表现一致 |
| 长时间播放 | 不被系统杀掉                           |


## B7. 收尾

```bash
adb uninstall com.biliseek.debug     # 需要时卸载
```

拔线即可。

# Part C · 真机无线测试

**用途**：验证真实使用姿态——边走边听、进电梯、Wi-Fi 切 4G。有线时这些没法测，因为人被线拴住了。

## C1. 首次配对（只需做一次）

**前提**：手机与电脑在**同一个 Wi-Fi** 下。

1. 手机：设置 → 开发者选项 → **无线调试** → 打开
2. 点「**使用配对码配对设备**」，手机会显示：
  - 配对码（6 位数字）
  - IP 地址和端口（形如 `192.168.1.7:37251`）

在电脑终端：

```bash
adb pair 192.168.1.7:37251
# 提示 Enter pairing code: 时输入手机上的 6 位配对码
```

成功会显示 `Successfully paired to ...`。

## C2. 连接

回到手机的「无线调试」主页，记下顶部的 **IP 地址和端口**（这个端口和配对端口**不是同一个**）：

```bash
adb connect 192.168.1.7:5555
adb devices
```

期望看到 `192.168.1.7:5555   device`。

> **常见坑**：配对用的端口是临时的，连接要用无线调试主页上显示的那个端口。搞混了会连不上。

## C3. 安装

```bash
cd ~/Documents/biliseek
./gradlew installDebug
adb shell pm clear com.biliseek.debug
```

**若同时连着模拟器或有线设备**，指定目标：

```bash
adb -s 192.168.1.7:5555 install -r app/build/outputs/apk/debug/app-debug.apk
```

## C4. 打开日志窗口

另开终端标签：

```bash
adb logcat -c && adb logcat -s BiliSeekAuth:V BiliSeekPlayUrl:V BiliSeekPlayer:V
```

> 无线日志会因网络波动断流。断了就重连一次 `adb connect`，日志窗口重新开。

## C5. 界面功能测试

**先把 Part B 的 B5 表格（步骤 1–14）在手机上走一遍**，确认基础功能正常。手机可以拿在手上操作，不用守在电脑前。

## C6. 移动场景专项

**这是走无线这条路径的真正理由。** 以下场景需要你带着手机走动。

### 步骤 16 — 边走边听

戴上耳机，播放音频，**把手机装进口袋走动 10 分钟**。


| 检查点       | 期望           |
| --------- | ------------ |
| 播放        | 全程不中断        |
| 息屏后       | 继续播放         |
| 中途掏出手机看锁屏 | 媒体控制卡片在，信息正确 |


### 步骤 17 — 网络切换

播放中从 Wi-Fi 覆盖区走到室外（切到移动网络）。


| 检查点  | 期望              |
| ---- | --------------- |
| 切换瞬间 | 播放可能短暂缓冲，但应自动恢复 |
| 不应   | 永久卡死、报错退出、静音    |


反向再试一次（4G 走回 Wi-Fi）。

### 步骤 18 — 弱信号与断连

进电梯 / 地下车库 / 信号盲区。


| 检查点     | 期望                  |
| ------- | ------------------- |
| 缓冲区内    | 继续播放不受影响            |
| 缓冲耗尽    | 卡住但**不崩溃**          |
| 出电梯恢复信号 | **自动续上**，不需要手动重新点播放 |


### 步骤 19 — 飞行模式

播放中打开飞行模式 20 秒，再关掉。


| 检查点    | 期望          |
| ------ | ----------- |
| 开飞行模式时 | 缓冲耗尽后卡住，不崩溃 |
| 关飞行模式后 | 自动恢复播放      |


### 步骤 20 — 息屏长播

息屏播放 **30 分钟**，中途不动手机。


| 检查点 | 期望                             |
| --- | ------------------------------ |
| 播放  | 不中断、不被系统杀掉                     |
| 耗电  | 听模式下应明显低于看模式（设置 → 电池 → 用量详情对比） |


> 这条特别重要：BiliSeek 的定位是「默认只听」，用户绝大多数时间就是息屏放口袋里。

## C7. 断连后重连

无线调试经常掉，掉了不影响手机上的 App，只影响电脑这边的日志和命令：

```bash
adb connect 192.168.1.7:5555     # 重连
```

手机重启或换 Wi-Fi 后需要重新走 C1 配对。

## C8. 收尾

```bash
adb disconnect 192.168.1.7:5555
```

手机上关掉「无线调试」开关（不关的话待机耗电略高）。

# 附录 1：日志查看详解

## 1.1 App 的四个日志 tag


| Tag               | 内容                              | 什么时候看            |
| ----------------- | ------------------------------- | ---------------- |
| `BiliSeekAuth`    | 风控凭据的种植、恢复、失败                   | 搜索没结果、启动异常       |
| `BiliSeekPlayUrl` | 取流、MPD 组装、URL 缓存命中              | 点了播不出来           |
| `BiliSeekPlayer`  | **EventLogger**——轨道选择、解码器、缓冲、首帧 | 验证切看是否真的省流量      |
| `BiliSeekHttp`    | 完整 HTTP 请求与响应头                  | 接口报错、怀疑签名/Cookie |


## 1.2 基本用法

```bash
# 实时看（推荐先清屏，避免历史日志干扰）
adb logcat -c && adb logcat -s BiliSeekPlayer:V

# 同时看多个 tag
adb logcat -s BiliSeekAuth:V BiliSeekPlayUrl:V BiliSeekPlayer:V

# 只导出已有日志不持续输出（-d = dump）
adb logcat -d -s BiliSeekAuth:V

# 存到文件事后分析
adb logcat -d > /tmp/biliseek.log

# 只看本 App 进程的全部日志
adb logcat --pid=$(adb shell pidof com.biliseek.debug)

# 看崩溃
adb logcat -d -s AndroidRuntime:E | grep -A 20 FATAL
```

## 1.3 关键日志长什么样

**启动时的凭据（首次）**

```
D BiliSeekAuth: buvid 激活: code=0
D BiliSeekAuth: 风控凭据种植完成
```

**启动时的凭据（后续）**

```
D BiliSeekAuth: 凭据从本地恢复，跳过网络请求
```

**取流成功**

```
D BiliSeekPlayUrl: MPD 组装完成：视频轨 6 条，音频轨 3 条
```

**重播命中缓存**（不应重复请求 playurl）

```
D BiliSeekPlayUrl: playurl 命中缓存 BV1GJ411x7h7:137649199:false
```

## 1.4 验证「听模式真的没下载视频」

这是最容易被表象骗过去的一项——**画面消失不等于视频轨被禁用**。

```bash
adb logcat -c && adb logcat -s BiliSeekPlayer:V
```

然后在 App 里切听/看，观察：

**切到看模式时**

```
videoEnabled            [eventTime=..., mediaPos=44.66]
videoDecoderInitialized [... c2.goldfish.hevc.decoder]
renderedFirstFrame      [... Surface(...)]
```

**退回听模式时**

```
videoDisabled  [eventTime=..., mediaPos=79.75]
rendererReady  [... rendererIndex=0, video, false]     ← 视频渲染器已释放
```

**轨道选择表**（EventLogger 会打印）：

```
tracks [...
  group [ id=1
    [ ] Track:0, mimeType=video/avc, res=320x142      ← [ ] = 未选中
    [X] Track:1, ...                                   ← [X] = 已选中
```

听模式下所有视频轨都应是 `[ ]`。

> 为什么较真：`clearVideoSurface()` 同样会让画面消失，但视频轨可能仍在下载解码——那样省电省流量的承诺一点没兑现。**只有日志能证明。**

## 1.5 系统状态速查

```bash
# 播放服务是否活着、前台类型对不对
adb shell dumpsys activity services | grep -A 8 PlaybackService

# 媒体会话（锁屏/通知栏控制的前提）
adb shell dumpsys media_session | grep -E "package=com.biliseek|state=PlaybackState"

# 是否在画中画
adb shell dumpsys activity activities | grep -i PictureInPictureMode

# 内存
adb shell dumpsys meminfo com.biliseek.debug | grep "TOTAL PSS"
```

## 1.6 界面内的自检卡片

有一项**不需要看日志**：切听/看时，播放页会直接显示诊断结果。

```
✓ 切换无缝：听 → 看
buffering 次数      0   (须为 0)
seek 不连续次数     0   (须为 0)
位置 25340ms → 25342ms
```

出现 `✗` 即失败。这是把验收判据做进了 App 本身。

# 附录 2：排查手册


| 现象                              | 优先排查                                                           |
| ------------------------------- | -------------------------------------------------------------- |
| 搜索一直没结果、也没错误                    | buvid 未激活。`adb shell pm clear` 后重启，看日志有无「buvid 激活: code=0」     |
| 有数据但播不出声                        | 请求头缺 Referer，CDN 返回 403。看 `BiliSeekHttp` 日志                    |
| 接口返回 `-412`                     | WBI 签名参数集不对                                                    |
| 接口返回 `-352`                     | 触发风控。**别反复重试**，等一会儿再用                                          |
| 切看时声音断一下                        | 播放源被重建了。看自检卡片的 buffering / seek 计数                             |
| 关了画面但流量照跑                       | 只清了 surface 没禁用视频轨。看 `videoDisabled` 日志                        |
| PiP 窗口黑屏                        | 「进后台」判定误伤了 PiP                                                 |
| 切页签时声音中断                        | MiniPlayer 被卷进了导航重组                                            |
| 点了播放没反应                         | 可能续播到了结尾。看日志有无 `state ... ENDED`                               |
| `adb devices` 显示 unauthorized   | 手机上没点授权，重新拔插看弹窗                                                |
| `adb devices` 显示 no permissions | udev 规则缺失，`sudo apt install android-sdk-platform-tools-common` |
| 无线调试连不上                         | 配对端口与连接端口不是同一个；确认在同一 Wi-Fi                                     |
