# Part A · 模拟器测试

## A1. 启动模拟器

```bash
cd <项目目录>
emulator -avd BiliSeek_API35 &
```

等待开机完成（约 1–2 分钟）：

```bash
adb wait-for-device
adb shell getprop sys.boot_completed        # 返回 1 即就绪
```

### 创建 AVD（如不存在）

项目要求：API 35（Android 15）、Google APIs x86_64、Pixel 7 设备配置、4 GB RAM。

```bash
# 1. 确认 system-image 已安装
sdkmanager --list | grep "system-images;android-35;google_apis;x86_64"
# 未安装则执行：
sdkmanager "system-images;android-35;google_apis;x86_64"

# 2. 创建 AVD
avdmanager create avd -n BiliSeek_API35 \
  -k "system-images;android-35;google_apis;x86_64" \
  -d "pixel_7" --force

# 3. 写入项目定制配置（覆盖默认值）
cat > ~/.android/avd/BiliSeek_API35.avd/config.ini << 'CONF'
AvdId=BiliSeek_API35
PlayStore.enabled=false
abi.type=x86_64
avd.ini.displayname=BiliSeek_API35
avd.ini.encoding=UTF-8
disk.dataPartition.size=4G
hw.cpu.ncore=4
hw.gpu.enabled=yes
hw.gpu.mode=swiftshader_indirect
hw.keyboard=yes
hw.lcd.density=420
hw.lcd.height=2400
hw.lcd.width=1080
hw.ramSize=4096
hw.sdCard=yes
hw.sdCard.size=512M
image.sysdir.1=system-images/android-35/google_apis/x86_64/
skin.dynamic=yes
tag.display=Google APIs
tag.id=google_apis
vm.heapSize=576
CONF

# 4. 验证
emulator -list-avds    # 应输出 BiliSeek_API35
```

### 虚拟机启动问题解决

```bash
emulator -list-avds                          # 先看 AVD 名字

emulator -avd <你的AVD名> -no-snapshot-load    # 冷启动一次（跳过损坏的 snapshot）

emulator -avd <你的AVD名> -wipe-data           # 或彻底重置
```

## A2. 安装并清空旧数据

```bash
./gradlew installDebug
adb shell pm clear com.biliseek.debug       # 清数据，以便测首次启动
```

## A3. 打开日志窗口

**另开一个终端标签**，保持它一直开着：

```bash
adb logcat -c && adb logcat -s BiliSeekAuth:V BiliSeekPlayUrl:V BiliSeekPlayer:V
```

后面每一步都可以回头看这个窗口。日志的详细读法见 [附录 1](#附录-1日志查看详解)。

## A4. 界面功能测试

从这里开始**全部在模拟器界面上手动操作**，按顺序做。

### 步骤 1 — 首次启动

在启动器里点开 **BiliSeek**。


| 检查点  | 期望                                           |
| ---- | -------------------------------------------- |
| 首屏   | 搜索框下面是引文式 slogan：左边一个淡色大引号「“」，下面一行**斜体衬线**「Seek and you shall find.」（比原来大得多，与标题同一套字体），再下面一条短横线引出「探索你的 B 站」；整块和标题、搜索框左对齐，**不是空白页**（这块只在无搜索历史、无播放记录时出现）。大引号**不压住**下面的「Seek」（2026-10-05 修过一次重叠）。深浅色模式下引号和短横线都跟着主题强调色走；系统字体调大一档以上时英文会折成两行，不应溢出屏幕 |
| 底部导航 | 「搜索 / 动态 / 列表 / 设置」四个（无推荐页仍是产品身份，动态 = 你关注的人）       |
| 标题栏 | 顶部显示「BiliSeek」（衬线字体：「Bili」正体、「Seek」斜体并取主题强调色）+ 账号名（未登录显示「未登录」），右侧头像圆圈 |
| 点头像 | 未登录：弹浮框「请在设置中登录」，连点不排队；已登录：进入自己的 UP 空间 |
| 通知权限 | Android 13+ 弹一次授权框，**选允许或拒绝都应能继续用**          |
| 日志窗口 | 出现「风控凭据种植完成」                                 |


### 步骤 2 — 搜索

顶部输入框输入 `music`（模拟器的 adb 输入法打不了中文，用界面软键盘可以打中文），**按输入法回车键搜索**（没有「搜索」按钮）。


| 检查点  | 期望                                    |
| ---- | ------------------------------------- |
| 结果头部 | 筛选条下面直接是结果，**没有**「约 N 个结果 · 第 X/Y 页」统计行（已按定稿删除；只有「UP 主」模式还显示「约 N 个 UP · 第 x/y 页」） |
| 结果条目 | 标题、UP 主、时长、播放量四项齐全；行尾是「⋮」按钮                    |
| **封面** | 每行左侧有 16:9 缩略图，**图能出来不是灰块**（灰块=加载失败） |
| 标题文字 | **不应出现 `&amp;quot;` 或 `<em>` 这类残留符号** |
| 圆叉清空 | 输入内容后文本框尾部出现 ✕，点击一键清空             |
| 筛选项位置 | 「视频 / UP 主」与排序、时长筛选只在**搜索结果上方**出现；首页不显示 |
| 搜索历史 | 未聚焦首页不显示；**点击搜索框聚焦后弹出**（可点、可删、可清空） |


> 封面加载失败多半是 Referer 没注入到图片请求上——B 站图片 CDN 校验热链，会返回 403。


### 步骤 3 — 分页

在结果列表里往下滑到底。


| 检查点  | 期望                    |
| ---- | --------------------- |
| 自动加载 | 滑到底自动加载下一页，新条目接在后面 |
| 内容   | 不重复、不跳号               |


### 步骤 4 — 点击播放

点任意一条单 P 结果（多 P 视频会先展开分 P 列表，见步骤 10）。


| 检查点  | 期望                           |
| ---- | ---------------------------- |
| 起播后  | **不自动打开播放页**：底部出现迷你播放条（封面、标题、细进度线），声音开始 |
| 点迷你播放条 | 打开播放页，顶栏中间是「正在播放」 |
| 视频区  | 显示**该视频的封面**——仍是**默认只听**，只是黑框换成了封面 |
| 进度   | 进度条推进，两端显示 `mm:ss`（超一小时为 `h:mm:ss`），**右侧不应是 `00:00`** |
| 日志窗口 | 出现「MPD 组装完成：视频轨 N 条，音频轨 M 条（音质 …）」 |


> 没有封面来源时（如某些外部分享直接起播的情况），封面区是灰色音符图标，属正常。

### 步骤 5 — 拖动进度条

在播放页把进度条**拖到中间某处再松手**。


| 检查点   | 期望                                  |
| ----- | ----------------------------------- |
| 松手瞬间  | 位置停在松手处，左侧时间同步更新                    |
| 松手 3 秒后 | **继续往前走，不回弹到拖动前的位置** ← 关键           |
| 拖动过程中 | 数字跟着手指走，不被后台轮询拽回                    |


> 回弹说明 UI 直接绑了播放器状态：250ms 一次的状态轮询会在手指还没松开时把值覆盖掉。

紧接着验「拖完就走也不丢」——**拖动后 3 秒内**执行：

```bash
adb shell am force-stop com.biliseek.debug
adb shell am start -n com.biliseek.debug/com.biliseek.app.MainActivity
```


| 检查点      | 期望                        |
| -------- | ------------------------- |
| 热力图今天的格子 → 当日播放记录里点这一条 | 从**刚拖到的位置**接着播，不是拖动前的旧位置（首页的「最近播放」已移除；当日记录的行上不显示进度） |


> 位置平时每 5 秒才回写一次。拖完立刻被杀还能保住，说明 seek 触发了强制回写。

### 步骤 6 — 倍速

点播放页「听 | 看」开关左边的「倍速」胶囊，在弹出的「倍速播放」弹层里依次点 `0.75×` → `1.5×` → `1×`（档位 0.5× ～ 3×）。


| 检查点  | 期望                     |
| ---- | ---------------------- |
| 选中态  | 弹层里当前倍速的档位高亮，只高亮一个；页面上的胶囊变主色、写当前档位（`1.5×`），回 `1×` 变回灰色「倍速」        |
| 声音   | **音调不变**，只是快慢变化（不是「花栗鼠音」）|
| 进度   | 1.5× 时进度推进明显变快          |


> 音调是否失真只能靠耳朵，模拟器没有音频输出时这条留到真机。

### 步骤 7 — 睡眠定时

点播放页「听 | 看」开关右边的「定时」胶囊，弹出「定时关闭」弹层（15 / 30 / 60 分钟 + 播完当前）。


| 操作          | 期望                                |
| ----------- | --------------------------------- |
| 点「15 分钟」    | 胶囊变主色、显示剩余时间（`14:5x`）并逐秒递减；再打开弹层，标题下有「剩余 14:5x」，右上出现「取消」        |
| 点「取消」       | 剩余时间消失，胶囊回到灰色「定时」                   |
| 点「播完当前」     | 胶囊写「播完当前」，弹层里该项高亮           |
| 先切「单曲」循环，再点「播完当前」，等这首放完 | **应当停下**，而不是原地重播 ← 关键 |


> 最后一条是这个功能的真正判据：终止条件必须**优先于播放模式**。
> 想完整验 15 分钟倒计时，设完就锁屏放着，到点回来看是否已暂停（且暂停位置在曲目中段，不是曲末）。

### 步骤 8 — 一键切看（核心卖点）

点播放页下方「听 | 看」开关里的「**看**」。


| 检查点  | 期望                                        |
| ---- | ----------------------------------------- |
| 画面   | 3 秒内出现在原来的封面区，**页面不跳转**                   |
| 声音   | **不中断、不重复、进度不跳** ← 这才是关键                  |


再点开关里的「**听**」，声音同样不应有任何断点。

**接着验「看模式下换内容会回到听」**——在播放页内嵌看时点「下一首」（或用通知栏 / 耳机切下一首）：


| 检查点 | 期望 |
| ---- | ---- |
| 呈现态 | **回到听模式**：显示封面（无封面来源时是灰色音符图标），「听 \| 看」开关停在「听」 |
| 不应 | 一块**没有画面的黑框** + 开关还停在「看」 ← 这正是修掉的那个 bug |


> 产品取向是「在播放页内嵌看时切下一首回到听」（全屏例外：接着全屏看，见步骤 23）。起播本来就会禁掉视频轨，
> 呈现态必须跟着复位——只禁轨不复位，界面就会以为还在看模式。
> **PiP 是例外**：那是系统窗口，关掉轨只会剩一个黑窗。

耳朵之外还要**用日志坐实**——切换前先清屏，两个方向各切一次：

```bash
adb logcat -c && adb logcat -d -s BiliSeekPlayer:V > /tmp/switch.log
grep -ic buffering /tmp/switch.log              # 必须是 0
grep -ic positionDiscontinuity /tmp/switch.log  # 必须是 0
```

两个计数**只要不是 0 就是失败**，说明切换时重新缓冲了或做了 seek。再看 `mediaPos` 是否连续：

```
videoDisabled [eventTime=141.16, mediaPos=75.62]      ← 看 → 听
videoEnabled  [eventTime=166.18, mediaPos=100.64]     ← 听 → 看
renderedFirstFrame [eventTime=166.69, mediaPos=101.18]   首帧 0.54 秒
```

**再验回到迷你播放条。** 先在播放页切到「看」，再分别用下面几种方式离开播放页：

| 离开方式 | 期望 |
| ---- | ---- |
| 点底部四个页面中的任一个（搜索 / 动态 / 列表 / 设置） | 播放页**收起成迷你播放条**并切到那个页面；画面没了，**自动切成听**，声音不中断、进度不跳 |
| 点的是打开播放页前所在的那个页面 | 同样收起成迷你播放条，留在那个页面 |
| 切到别的页面再切回来 | 播放页**不会自己又冒出来** |
| 系统返回手势 | 同样收起并切成听（以前是收起了还在解码视频）；**画面停在最后一帧，和整页一起淡出**（以前其他内容先淡没、视频窗口最后才消失） |
| 播放页左上「收起」箭头 | 同上，画面定格后和整页一起淡出，不会先跳成封面 |
| 在看、播放中，长按播放页上的小画面 | 震一下，画面中间显示「2× 加速中」（无损时「1.5× 加速中」），声音和画面变 2 倍速（在听无损音质时是 1.5 倍）；松手恢复原来的速度。暂停时长按没反应；已经是 2 倍及以上时长按不变 |
| 播放页里点「查看UP主」 | 进 UP 空间，迷你播放条出现、已切成听 |
| 全屏时按返回 | 先退回播放页，**仍在看**（全屏不算回到迷你条） |
| 按 Home 进画中画 | 仍在看（画中画不算回到迷你条） |

**「起播模式：记住上次」**（设置里选上）：
- 在播放页切到「看」后收起，再点迷你播放条打开播放页，会**自动切回看**。
- 在播放页亲手点「听」后收起，再打开，保持听。
- 从列表里点一个新视频起播，在迷你播放条上**一直是听**；点开播放页才按「上次」切成看。
- 设置里这一项的说明是「上次离开播放页时在看，下次打开播放页直接进看模式」。

### 步骤 9 — 跨页面播放不中断

MiniPlayer 在播放时，依次点底部「列表」→「设置」→「搜索」。


| 检查点        | 期望              |
| ---------- | --------------- |
| 声音         | **全程不中断**       |
| MiniPlayer | 始终显示在底部，标题和进度正常 |
| 迷你条的样子 | 顶部**没有横杠**，只有一条细进度线（左右和封面、列表键对齐）；整条比以前矮一截 |
| 迷你条背后（「浮在底部」） | 卡片左右和下面的空隙里**能看到下面的页面**（滚动列表时内容从迷你条后面经过），不是一块实底色 |
| 迷你条背后（「贴底」，设置 → 界面 → 迷你播放器样式） | 左右上角圆角外**能看到下面的页面** |
| 各页面滑到最底（搜索结果、动态、列表页各 tab 与内页、稍后再看、合集、已下载、AI 总结、听歌历史、榜单、UP 空间、关注列表、消息、设置） | 最后一条**停在迷你条上方**，不被挡住；迷你条收成小横杠时留白跟着变小 |
| 私信页、下拉刷新的提示 | 输入框、提示都在迷你条上方，不被挡住 |
| 在进度线附近左右拖 | 每挪一小段（约 2 毫米）前进 / 后退 **5 秒**并**震一下**；时间文字变成蓝色粗体，显示松手后跳到哪；线变粗、出现圆点；**松手才跳**，拖回原处松手不跳 |
| 拖到开头 / 结尾 | 停在 00:00 / 总长，再往外拖不再震 |
| 轻点进度线 | 不跳 |
| 在进度线上**按住约半秒不动** | 震一下；迷你条上方浮出刻度尺：整条只代表按住处前后共 3 分钟，每 5 秒一小格、整分钟标时间；主色指针在手指正上方，上面大字是按住处的时间（对齐到 5 秒） |
| 按住后左右拖 | 指针跟着手指、停在 5 秒的格上，每换一格震一下；迷你条里的时间同步变；拖到刻度尺两端外就停在两端；这时上下动手指**不会**打开 / 收起迷你条 |
| 按住后松手 | 跳到选中的时间，刻度尺消失；和按下前的位置一样就不跳 |
| 不到 3 分钟的视频按住 | 刻度尺就是整个视频，两端是开头和结尾 |
| 在迷你条上往上滑 / 往下滑 | 往上打开播放页；往下把迷你条收成一条小横杠，往上拉横杠恢复 |
| 震动没感觉时 | 看系统设置里的「触感反馈 / 触摸振动」是否打开（震动跟随这个开关） |


### 步骤 10 — 多 P 视频

搜索 `album`，找一条专辑合集类的结果点进去。


| 检查点    | 期望                               |
| ------ | -------------------------------- |
| 搜索结果里  | 这个视频**只占一条**（折叠）                 |
| 点入后    | 展开成「BVxxxx · N 个分 P」列表，含「返回结果」按钮 |

| 检查点    | 期望                    |
| ------ | --------------------- |
| 长按满时间 | 手机**震一下**；那一行变成**浮起的圆角卡片**（带阴影、略放大），右侧三点换成**主色的拖动手柄** |
| 拖动中    | 卡片跟着手指走；**别的行滑开让位**，空出来的格子就是落点；每让一格**轻震一下**。**按住不动等长按触发再拖**才是排序，直接横滑是移除 |
| 拖到列表上下边缘（列表比一屏长时） | 列表**自动滚动**，越靠边越快，能把条目拖到原来在屏幕外的位置 |

| 拖第一屏最上面那一行往下 | 列表本身不跳 |
| **杀进程重开再进该歌单** | **顺序保持** ← 关键，证明写进了数据库而不只是动画 |

### 步骤 14 — 首页空状态与搜索历史

回搜索页，**把搜索框的字清空**。

| ----- | --------------------- |
| 搜索历史（未聚焦） | **不直接显示**——首页只显示 slogan（新用户）/ 播放热力 / 快捷入口（每周必看、入站必刷、热歌榜、原创音乐榜、热门播客、视频播客、全站排行榜，不需要登录；可在 设置 → 界面 → 首页快捷入口 里关闭和排序） |
| 聚焦搜索框 | **搜索历史弹出**：关键词标签（每个带 ✕）、右上「清空」 |

| 点 ✕   | 删掉该条历史                |
| 点历史外空白 | 历史收起、键盘收起，回首页空状态   |
| 播放热力  | 今天的格子出现颜色，**深浅随当天听的分钟数变化**（不足 10 分钟最浅，10 / 30 / 60 分钟各深一档）；点它进入当日播放记录，条目带**封面**、标题，下面一行「UP 主 · 听了 mm:ss」（这天听了多久；10-07 以前的日子仍显示视频时长） |

| 点「入站必刷」 | 副标题是官方那句「我不允许还有人没看过这N个宝藏视频！」；列表同上 |
| 点「热歌榜」 | 副标题「第 N 期」；顶栏下同样有一排「第N期」选择条（最新在最左，默认选中）；每行左侧有名次，前三名用主题色；**榜单内容和 B 站 App「音乐榜」对得上** ← 关键 |
| 在「每周必看」「热歌榜」里切换期数 | 点另一期，列表和副标题换成那一期（第一次切到会有一下加载）；切回看过的期是立刻出来的；**往前翻很久以前的期数也能取到内容** ← 关键（接口只对照过文档，没对照过真实响应） |
| 连续快速点好几个期数 | 最后点的那一期的内容才会显示，中间几期不会闪回、不会报错（每次请求之间有 0.6–0.9 秒的间隔，所以会稍慢） |
| 「每周必看」「热歌榜」下拉刷新 | 重新取期数列表和当前这一期，选择条与列表都刷新，仍停在当前这一期 |

| 设置保留 | 时间模式、范围、排序、「隐藏 1 分钟以下」杀进程重开后保持；按月份与最近 7 天会按当天重算 |

### 步骤 16 — 接住外部分享

**真机上**：在 B 站 App 里找个视频 → 分享 → 选 BiliSeek。
或在浏览器里打开一个 b23.tv 链接 → 选 BiliSeek 打开。

**模拟器上**用命令模拟：

```bash
# 模拟「分享到」（ACTION_SEND）
adb shell am start -a android.intent.action.SEND -t text/plain \
  --es android.intent.extra.TEXT "'【标题】 - 哔哩哔哩 https://b23.tv/BV17x411w7KC 快来看'" \

# 模拟浏览器点链接（ACTION_VIEW）
adb shell am start -a android.intent.action.VIEW \

```


| 场景                | 期望                       |
| ----------------- | ------------------------ |
| App 没开时分享         | 冷启动后**直接起播**（分享过来的仍然直接播；只有搜索框里自己输入的才先显示结果） |

> **务必验证「登录非强制」**：全新安装后不登录，直接走完步骤 2–16。这是产品身份的一部分。

**登录态续期**（Cookie 刷新）：M9 已填入 `CORRESPOND_PUBLIC_KEY`（来源见 `CookieRefresher.kt` 的注释），
日志里会看到：

```
D BiliSeekRefresh: 启动时检查登录态续期：NotLoggedIn      ← 未登录时
D BiliSeekRefresh: 启动时检查登录态续期：NotNeeded        ← 服务端说还不用刷
D BiliSeekRefresh: 启动时检查登录态续期：Refreshed        ← 刷新成功
D BiliSeekRefresh: 登录态已续期                          ← 刷新成功
D BiliSeekRefresh: 启动时检查登录态续期：Failed(…)        ← 链路某一步失败（会保持现有登录态）
D BiliSeekRefresh: 启动时检查登录态续期：Expired          ← passport 也回 -101：登录态已失效（第一个账号请求撞 -101 时自动登出）
```

> 拿到真人账号前，`Refreshed` 分支**没有实测过**——公钥有字节级出处证据（线上 wasm 比对），
> 但端到端刷新仍需一次真实登录验证，见 [附录 3](#附录-3已知缺口)。

**登录态失效（`-101`）**：账号请求撞 `-101` 时先续期一次，续上了重打一次；passport 也说失效才自动登出。真人验证：

1. 已登录状态下，在 B 站网页或 App 的账号安全里下线这台设备（或改密码），让 BiliSeek 的登录态在服务端失效；
2. 回到 BiliSeek，进动态页或下拉刷新收藏夹；
3. 预期：各账号页回到登录面板，面板显示「登录失败：登录已过期，请重新扫码」；日志有
   `W BiliSeekLogin: passport 确认登录态已失效，已自动登出`；同一时段 `BiliSeekHttp` 里 `cookie/info` 只出现一次。

「续上后重打」要等服务端判定该续期（`cookie/info` 回 `refresh: true`）才走得到，无法人为构造，保持**未验证**。

### 步骤 32 — AI 视频总结（0.4.1 新增，规则见 `docs/archive/10-AI总结-实现工单.md`）

> ⚠️ 这一步会真实请求 B 站（字幕 / 官方总结）和你配置的 AI 服务（MiniMax 等），**只能人工做**，自动化测试不碰这些服务。
> 每次「打开弹窗」对 B 站各请求一次（官方总结 + 字幕列表），同一视频反复打开只请求一次；测的时候别连点。

**准备**：设置 → AI 总结：填 Base URL、API Key、模型名（没有默认模型名，必填），点「测试连接」。

| 检查点 | 期望 |
| ---- | ---- |
| 故意填错 Key 后「测试连接」 | 提示 Key 无效，且之后点总结**不会**先去下载音频 / 识别 |
| 有字幕的视频 → 点播放页「总结」 | 弹出风格弹窗；有 B 站官方总结时「使用 B 站 AI 总结（免费）」可选；下方有 4 种风格 + 原文笔记 |
| 设置里「默认选择」选「B 站总结」 / 选某个风格 | 弹窗默认选中设置的那一项；选风格时即使有官方总结也默认选该风格；在弹窗里手动点过后不会被查询结果改掉 |
| 选一种风格开始 | 阅读页底部面板出现，显示阶段与进度，正文流式出现；完成后有通知 |
| 阅读页：上拉 / 点右上角全屏按钮 | 面板撑满；下拉回 60%，再下拉关闭 |
| 点正文里的 `[mm:ss]` 时间戳 | 当前加载的就是这条视频：原地跳转，**暂停中也接着播**；不是这条：从该位置开始播放（默认听） |
| 再点一次「生成新版本」 | 旧版本保留，顶部出现「版本 2/2」可切换；可分别删除；「删除全部版本」连原文一起清 |
| 分享 / 另存为 | 得到内容一致的 `.md` |
| 点顶部的「版本 2/2 ▾」 | 底部弹出「切换版本」操作表（当前版本前有「✓」，失败 / 生成中的带后缀），点一项切过去 |
| 点右上角「更多」 | 底部弹出操作表（不再是贴着图标的小菜单）：另存为… / 查看原文 / 生成新版本（生成中时是「取消生成」）/ 删除此版本 / 删除全部版本，**删除类红字并带删除图标** |
| 总结完成后回到播放页 | 「总结」按钮变成实心（主题色），和点赞 / 投币后的形式一致 |
| 「列表」页的「已下载」「AI 总结」两行 | 右侧只写条数「N 项」（以前是「N 个」，AI 总结还带占用大小，现在不带）；有下载在进行时顶部是「下载中 N 项」；收藏夹页每个收藏夹下面是「N 项 · …同步」 |
| 「播放列表」页 → 「AI 总结」 | 列出所有总结与各自占用空间（占用只在这一页看）；点一行打开这份总结 |
| AI 总结列表每行右侧的播放键 | 播这份总结对应的视频（多 P 视频播总结的那一 P） |
| AI 总结列表右滑一行 | 这一行消失、顶部总占用跟着减，底部「已删除「标题」的总结 · 撤销」；点撤销放回；不撤销约 5 秒后真删（重进页面也不在了） |
| AI 总结列表顶部的垃圾桶 | 先确认「清空全部 AI 总结？」，确认后全部删除 |
| 总结中途开飞行模式 | 显示「等待网络后自动继续」；关闭后自动继续，不重复已完成的分块 |
| 失败后（如额度用尽 / 改错模型名） | 阅读页顶部给出出路：重试 / 改用备用模型（需确认）/ 原文笔记 / 去设置；不会自动重试 |
| 选「原文笔记」 | 不发任何 AI 请求即完成 |
| 无字幕视频：设置里下载（或导入）离线识别模型后总结 | 先下载音频再在本机识别（已在「已下载」里的视频完全离线）；通知里显示「本地识别 mm:ss / mm:ss」；识别中杀进程，重开后从断点继续 |
| 模型下载提示「校验失败」 | 说明下载源的文件与官方包不一致：从 sherpa-onnx 发布页下载压缩包解压后，在设置里「导入文件」同时选 `model.int8.onnx` 与 `tokens.txt` |

## A5. 模拟器特有场景

### 断网表现与错误重试

**要测到真东西，得先把凭据清掉**——否则凭据还在缓存里，走不到出问题的那条路径：

```bash
adb shell pm clear com.biliseek.debug
adb shell pm grant com.biliseek.debug android.permission.POST_NOTIFICATIONS
adb shell am start -n com.biliseek.debug/com.biliseek.app.MainActivity
sleep 15                                       # 让后台预热跑进退避
adb shell cmd connectivity airplane-mode enable
```

然后在界面上点播放（或发一个链接进去）。


| 操作            | 期望                                        |
| ------------- | ----------------------------------------- |
| 断网后杀掉 App 重开  | **界面完整、搜索框能输入**，不白屏不 ANR                  |
| 断网时点播放        | **5 秒内**出现「取流失败」+「**重试**」按钮，不是无限转圈        |
| 断网时搜索         | 出现「网络不可用」+「重试」，**不是白屏**                   |


> 这条曾经要等约 85 秒——后台预热与用户请求共用一份重试预算，用户只能排队干等。
> 现在两条路径预算分开，前台**只试一次就报错**。

用日志确认「没有排队」：

```bash
adb logcat -d -v time | grep -E "FOREGROUND|BACKGROUND"
```

应看到两条链**各走各的**（前台只有「第 1 次」，后台在自己按 1/2/4/8 秒退避）：

```
07:21:05.117 W BiliSeekAuth: 凭据获取失败（第 1 次，FOREGROUND）：Unable to resolve host
07:21:05.423 W BiliSeekAuth: 凭据获取失败（第 5 次，BACKGROUND）：Unable to resolve host
```

**恢复网络后点「重试」**：

```bash
adb shell cmd connectivity airplane-mode disable
```


| 操作     | 期望                                    |
| ------ | ------------------------------------- |
| 点「重试」  | 一次点击内完成「重新种植凭据 → 取流 → 起播」             |
| 日志     | `风控凭据种植完成` 紧跟 `MPD 组装完成`              |


> 若「重试」按钮被软键盘挡住，先按一次返回键收键盘。

### 错误分类与「不该出现的重试按钮」


| 错误                | 文案                    | 是否给「重试」按钮       |
| ----------------- | --------------------- | --------------- |
| 网络不可用             | 「网络不可用」               | ✅ 给             |
| 设备凭据失效（-412）      | 「设备凭据已失效，已重新种植」       | ✅ 给             |
| 凭据未激活             | 「设备凭据尚未激活…」           | ✅ 给             |
| 搜索无结果             | 「没有找到「xxx」」           | ❌ **不给**（重试也没有） |
| **触发风控（-352）**    | 「请求太频繁，B 站暂时拦截了搜索」    | ❌ **绝不给** ← 硬判据 |


> **别为了看这条截图去猛刷搜索。** `-352` 的正确处置就是等，
> UI 不给按钮正是为了避免用户猛戳把临时限流拖成长期封禁。这条靠单测锁定，不实触发。

### 流量对比（验证「听模式省流量」）

⚠️ 模拟器的流量统计是**粗粒度轮询**，不强制刷新会一直读到 0：

```bash
adb shell dumpsys package com.biliseek.debug | grep appId      # 取 uid
adb shell dumpsys netstats --poll                              # 必须先这句
adb shell dumpsys netstats detail | grep -A 12 "uid=<你的uid>"
```

分别在听模式和看模式各播 1 分钟，对比 `rb=` 增量。预期是**量级差异**（实测约 160 倍）。

**设置 → 网络和互联网 → 流量使用 → BiliSeek**

分别在听模式和看模式各播 5 分钟，对比消耗。预期是量级差异。

### 步骤 39 — Hi-Res（需大会员账号）

⏸ **当前跑不了：开发者没有大会员账号。** 按《功能优化篇》§2.4 的口径，
这类功能**照常实现、只验逻辑、验收记录里如实标注未验证**，不做真机验收。

拿到会员账号之后，这一步要补的是：

1. 设置页音质选「无损优先」，播一条带 Hi-Res 的视频
2. 三点菜单 →「音质」弹层里**不出现**「这个视频没有无损 / 杜比音轨，或账号没有权限，当前为普通音质」；全屏底栏音质按钮写「无损」
3. 取流日志里 `MPD 组装完成：…（音质 LOSSLESS，无损生效）`
4. 切到 2.0× → 自动回退 AAC，缓存 key 后缀变 `:AUTO`（这一支**没有会员也能验**，见步骤 22）

⚠️ **部分设备的系统 FLAC 解码器只分配 32 KiB 输入缓冲**，而 B 站 Hi-Res 单帧可能超过，会崩溃。**这个坑只在真机上撞得到。**

```bash
adb logcat -s BiliSeekPlayer:V | grep -iE "flac|InsufficientCapacity"
```

无账号期间，这条路径由逻辑测试兜底：`FlacBufferPolicyTest`（缓冲抬升的三条边界）、
`LosslessManifestTest`（无损轨真的写进了 MPD 且没挤掉视频轨）、`QualityPolicyTest`（回退判定）。

| 长时间播放 | 不被系统杀掉                           |

### 步骤 C-6 — 离线播放（M9 新增，飞行模式）

1. 打开飞行模式（彻底断网）
2. 从「已下载」或热力图的当日播放记录点这条
3. 播放中点「看」（只下了音频的 m4a 预期不切换、只给提示）

| 检查点 | 期望 |
| ---- | ---- |
| 飞行模式下起播 | **能播、不卡在风控凭据上**——离线拦截点在 `awaitReady()` 之前 |

> 这与步骤 C-4 是两条不同的线：C-4 验的是**在线内容**在断网下的恢复，
> 这条验的是**本地内容**在无网下的可播——地铁、飞机、信号盲区里 App 还能不能用的关键。

## 1.3 关键日志长什么样

**启动时的凭据（首次）**

```
D BiliSeekAuth: buvid 激活: code=0
D BiliSeekAuth: 风控凭据种植完成
```

**启动时的凭据（后续）**

```
D BiliSeekAuth: 凭据从本地恢复，跳过网络请求
```

**取流成功**

```
D BiliSeekPlayUrl: MPD 组装完成：视频轨 6 条，音频轨 3 条（音质 AUTO），线路 <CDN 主机> > <备用主机>
```

**重播命中缓存**（不应重复请求 playurl）

```
D BiliSeekPlayUrl: playurl 命中缓存 BV1GJ411x7h7:137649199:AUTO      ← key = bvid:cid:音质
```

**断网时的两条重试路径**（关键：前台只有「第 1 次」，且不排在后台后面）

```
W BiliSeekAuth: 凭据获取失败（第 1 次，FOREGROUND）：Unable to resolve host ...
W BiliSeekAuth: 凭据获取失败（第 5 次，BACKGROUND）：Unable to resolve host ...
```

若看到前台也在「第 2 次、第 3 次…」，说明快慢预算没拆开，错误会浮现得很慢。

**登录态续期检查**

```
D BiliSeekRefresh: 启动时检查登录态续期：NotLoggedIn      ← 未登录
D BiliSeekRefresh: 启动时检查登录态续期：NotNeeded        ← 服务端说还不用刷
D BiliSeekRefresh: 启动时检查登录态续期：Refreshed        ← 刷新成功
D BiliSeekRefresh: 登录态已续期                          ← 刷新成功
```

## 1.4 验证「听模式真的没下载视频」

这是最容易被表象骗过去的一项——**画面消失不等于视频轨被禁用**。

```bash
adb logcat -c && adb logcat -s BiliSeekPlayer:V
```

然后在 App 里切听/看，观察：

**切到看模式时**

```
videoEnabled            [eventTime=..., mediaPos=44.66]
videoDecoderInitialized [... c2.goldfish.hevc.decoder]
renderedFirstFrame      [... Surface(...)]
```

**退回听模式时**

```
videoDisabled  [eventTime=..., mediaPos=79.75]
rendererReady  [... rendererIndex=0, video, false]     ← 视频渲染器已释放
```

**轨道选择表**（EventLogger 会打印）：

```
tracks [...
  group [ id=1
    [ ] Track:0, mimeType=video/avc, res=320x142      ← [ ] = 未选中
    [X] Track:1, ...                                   ← [X] = 已选中
```

听模式下所有视频轨都应是 `[ ]`。

> 为什么较真：`clearVideoSurface()` 同样会让画面消失，但视频轨可能仍在下载解码——那样省电省流量的承诺一点没兑现。**只有日志能证明。**

| **弹幕只在全屏显示** | 产品决定（听为主，内联不喧宾夺主），不是漏做。高级 / 代码 / BAS 弹幕不渲染 |
| **弹幕某段加载失败不重试** | 风控规则（-352 不重试）；该段内无弹幕，换视频或重进 App 后重新请求 |
| **无损音质与 FLAC 解码兼容不做真机验收** | 开发者无大会员账号。按《功能优化篇》§2.4：照常实现、只验逻辑（`QualityPolicyTest` / `LosslessManifestTest` / `FlacBufferPolicyTest`）、**验收记录标未验证**。拿到账号后按步骤 39 补 |
| **榜单与活动页接口没对照过真实响应** | 每周必看 / 入站必刷 / 热歌榜的期数与内容、热门播客页解析、`x/article/cards` 都只按社区文档写（步骤 14 / 15）。热门播客只绑定一个运营活动页，换网址或改版就显示「热门播客页面结构变了，没能解析」——这是预期的失效方式，不是网络问题 |
| **充电角标只有三处标** | 只有 UP 空间投稿、动态里的视频、稍后再看标「充电」/「限免」；搜索结果（含搜 BV 号那一条）**有意不标**（接口不带充电信息）；收藏夹、榜单、合集还没有样本，没有角标不算 bug。蓝色「已充电」已去掉（步骤 30） |
| **几个写操作需真人账号验证** | 取消订阅合集、稍后再看 / 收藏夹右滑移除、「加入列表 → 稍后再看」（含已在稍后再看里的视频再加一次）只做了逻辑测试 |
| **深色模式冷启动闪一下浅色** | 设置里选了「深色」时，冷启动第一瞬间仍按系统颜色（XML 主题固定浅色），进入界面后才变深色；预期内 |
| **仪器化 UI 测试多数只编译过** | 功能优化篇 §13.31 起新增 / 改写的 androidTest 用例（含 `MigrationTest` 7→8、8→9）多数没在设备上跑；跑 `connectedDebugAndroidTest` 出现失败时先确认是不是用例本身过期 |

```bash
# ── 构建安装 ──
./gradlew installDebug
adb -s <序列号> install -r app/build/outputs/apk/debug/app-debug.apk

adb uninstall com.biliseek.debug                                       # 卸载

adb logcat -c && adb logcat -s BiliSeekPlayer:V
adb logcat -d -s AndroidRuntime:E | grep -A 20 FATAL

adb devices
adb connect 手机IP:5555
adb disconnect 手机IP:5555
adb emu kill                                                           # 关模拟器

# ── 抓证据 ──
adb exec-out screencap -p > /tmp/shot.png                              # 截图
adb shell screenrecord /sdcard/demo.mp4                                # 录屏，Ctrl+C 停
adb pull /sdcard/demo.mp4

# ── 网络开关（模拟器）──
adb shell svc wifi disable && adb shell svc data disable
adb shell svc wifi enable && adb shell svc data enable
adb shell cmd connectivity airplane-mode enable                        # 飞行模式，断得更彻底
adb shell cmd connectivity airplane-mode disable

  -d "https://www.bilibili.com/video/BV1Q541167Qg" com.biliseek.debug

./gradlew test                        # 单元测试，秒级
./gradlew connectedDebugAndroidTest   # 仪器化测试，需连设备
```
