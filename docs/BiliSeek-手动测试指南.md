# Part A · 模拟器测试

## A1. 启动模拟器

```bash
cd ~/Documents/biliseek
emulator -avd BiliSeek_API35 &
```

等待开机完成（约 1–2 分钟）：

```bash
adb wait-for-device
adb shell getprop sys.boot_completed        # 返回 1 即就绪
```



虚拟机启动问题解决：

emulator -list-avds                          # 先看 AVD 名字

emulator -avd &lt;你的AVD名&gt; -no-snapshot-load    # 冷启动一次

emulator -avd &lt;你的AVD名&gt; -wipe-data           # 或彻底重置



## A2. 安装并清空旧数据

```bash
./gradlew installDebug
adb shell pm clear com.biliseek.debug       # 清数据，以便测首次启动
```

## A3. 打开日志窗口

**另开一个终端标签**，保持它一直开着：

```bash
adb logcat -c && adb logcat -s BiliSeekAuth:V BiliSeekPlayUrl:V BiliSeekPlayer:V
```

后面每一步都可以回头看这个窗口。日志的详细读法见 [附录 1](#附录-1日志查看详解)。

## A4. 界面功能测试

从这里开始**全部在模拟器界面上手动操作**，按顺序做。

### 步骤 1 — 首次启动

在启动器里点开 **BiliSeek**。


| 检查点  | 期望                                           |
| ---- | -------------------------------------------- |
| 首屏   | 显示「Seek and you shall find.」+ 一行说明，**不是空白页** |
| 底部导航 | 「搜索 / 音乐库 / 设置」三个，**没有第四个**（无推荐页是产品身份）       |
| 通知权限 | Android 13+ 弹一次授权框，**选允许或拒绝都应能继续用**          |
| 日志窗口 | 出现「风控凭据种植完成」                                 |


### 步骤 2 — 搜索

顶部输入框输入 `music`（模拟器的 adb 输入法打不了中文，用界面软键盘可以打中文），点右侧「**搜索**」按钮。


| 检查点  | 期望                                    |
| ---- | ------------------------------------- |
| 结果头部 | 「约 N 个结果 · 第 1/M 页」                   |
| 结果条目 | 标题、UP 主、时长、播放量四项齐全                    |
| **封面** | 每行左侧有 16:9 缩略图，**图能出来不是灰块**（灰块=加载失败） |
| 标题文字 | **不应出现 `&amp;quot;` 或 `<em>` 这类残留符号** |


> 封面加载失败多半是 Referer 没注入到图片请求上——B 站图片 CDN 校验热链，会返回 403。


### 步骤 3 — 分页

在结果列表里往下滑到底。


| 检查点  | 期望                    |
| ---- | --------------------- |
| 自动加载 | 滑到底自动加载下一页，页码从 1/M 递增 |
| 内容   | 不重复、不跳号               |


### 步骤 4 — 点击播放

点任意一条结果。


| 检查点  | 期望                           |
| ---- | ---------------------------- |
| 播放器  | 自动展开，显示「正在播放」                |
| 视频区  | 显示**该视频的封面**（不再是「纯音频模式」四个字）——仍是**默认只听**，只是黑框换成了封面 |
| 进度   | 进度条推进，两端显示 `mm:ss`（超一小时为 `h:mm:ss`），**右侧不应是 `00:00`** |
| 日志窗口 | 出现「MPD 组装完成：视频轨 N 条，音频轨 M 条」 |


> 直接粘 BV 号播放时没有封面来源，此时仍显示「纯音频模式」，属正常。

### 步骤 5 — 拖动进度条

在播放页把进度条**拖到中间某处再松手**。


| 检查点   | 期望                                  |
| ----- | ----------------------------------- |
| 松手瞬间  | 位置停在松手处，左侧时间同步更新                    |
| 松手 3 秒后 | **继续往前走，不回弹到拖动前的位置** ← 关键           |
| 拖动过程中 | 数字跟着手指走，不被后台轮询拽回                    |


> 回弹说明 UI 直接绑了播放器状态：250ms 一次的状态轮询会在手指还没松开时把值覆盖掉。

紧接着验「拖完就走也不丢」——**拖动后 3 秒内**执行：

```bash
adb shell am force-stop com.biliseek.debug
adb shell am start -n com.biliseek.debug/com.biliseek.app.MainActivity
```


| 检查点      | 期望                        |
| -------- | ------------------------- |
| 首页「最近播放」 | 显示的是**刚拖到的位置**，不是拖动前的旧位置 |


> 位置平时每 5 秒才回写一次。拖完立刻被杀还能保住，说明 seek 触发了强制回写。

### 步骤 6 — 倍速

播放页下方「倍速」一排，依次点 `0.75×` → `1.5×` → `1.0×`。


| 检查点  | 期望                     |
| ---- | ---------------------- |
| 选中态  | 当前倍速的胶囊高亮，只高亮一个        |
| 声音   | **音调不变**，只是快慢变化（不是「花栗鼠音」）|
| 进度   | 1.5× 时进度推进明显变快          |


> 音调是否失真只能靠耳朵，模拟器没有音频输出时这条留到真机。

### 步骤 7 — 睡眠定时

播放页下方「睡眠定时」一排。


| 操作          | 期望                                |
| ----------- | --------------------------------- |
| 点「15 分钟」    | 标题变成「睡眠定时 · 剩余 14:5x」并逐秒递减        |
| 点「取消」       | 剩余时间消失，回到「睡眠定时」                   |
| 点「播完当前」     | 标题变成「睡眠定时 · 播完当前」，该胶囊高亮           |
| 先切「单曲」循环，再点「播完当前」，等这首放完 | **应当停下**，而不是原地重播 ← 关键 |


> 最后一条是这个功能的真正判据：终止条件必须**优先于播放模式**。
> 想完整验 15 分钟倒计时，设完就锁屏放着，到点回来看是否已暂停（且暂停位置在曲目中段，不是曲末）。

### 步骤 8 — 一键切看（核心卖点）

点「**切「看」**」按钮。


| 检查点  | 期望                                        |
| ---- | ----------------------------------------- |
| 画面   | 3 秒内出现在原来的封面区，**页面不跳转**                   |
| 声音   | **不中断、不重复、进度不跳** ← 这才是关键                  |


再点「**退回「听」**」，声音同样不应有任何断点。

**接着验「看模式下换内容会回到听」**——在看模式下点「下一首」，或收起播放器粘另一个链接：


| 检查点 | 期望 |
| ---- | ---- |
| 呈现态 | **回到听模式**：显示封面（无封面来源时显示「纯音频模式」），按钮是「切「看」」 |
| 不应 | 一块**没有画面的黑框** + 按钮写着「退回「听」」 ← 这正是修掉的那个 bug |


> 产品取向是「看模式下切下一首回到听」。起播本来就会禁掉视频轨，
> 呈现态必须跟着复位——只禁轨不复位，界面就会以为还在看模式。
> **PiP 是例外**：那是系统窗口，关掉轨只会剩一个黑窗。

耳朵之外还要**用日志坐实**——切换前先清屏，两个方向各切一次：

```bash
adb logcat -c && adb logcat -d -s BiliSeekPlayer:V > /tmp/switch.log
grep -ic buffering /tmp/switch.log              # 必须是 0
grep -ic positionDiscontinuity /tmp/switch.log  # 必须是 0
```

两个计数**只要不是 0 就是失败**，说明切换时重新缓冲了或做了 seek。再看 `mediaPos` 是否连续：

```
videoDisabled [eventTime=141.16, mediaPos=75.62]      ← 看 → 听
videoEnabled  [eventTime=166.18, mediaPos=100.64]     ← 听 → 看
renderedFirstFrame [eventTime=166.69, mediaPos=101.18]   首帧 0.54 秒
```

### 步骤 9 — 跨页面播放不中断

MiniPlayer 在播放时，依次点底部「音乐库」→「设置」→「搜索」。


| 检查点        | 期望              |
| ---------- | --------------- |
| 声音         | **全程不中断**       |
| MiniPlayer | 始终显示在底部，标题和进度正常 |


### 步骤 10 — 多 P 视频

搜索 `album`，找一条专辑合集类的结果点进去。


| 检查点    | 期望                               |
| ------ | -------------------------------- |
| 搜索结果里  | 这个视频**只占一条**（折叠）                 |
| 点入后    | 展开成「BVxxxx · N 个分 P」列表，含「返回结果」按钮 |
| 分 P 条目 | 显示「P1 曲名」和时长                     |
| 点某个 P  | 播放该 P，**核对播放页时长与列表标注是否一致**       |


### 步骤 11 — 队列与队列面板

接着上一步（播放某个分 P 后）。


| 检查点           | 期望                            |
| ------------- | ----------------------------- |
| 队列显示          | 播放页显示「队列 N / M」，右侧有「展开」       |
| 点「展开」         | 列出**全部**队列条目，带序号；当前项高亮且标「正在播放」 |
| 点列表里第 3 项     | 直接跳到第 3 项播放，顶部变成「队列 3 / M」     |
| 点「收起」         | 列表收起，只剩「队列 N / M」一行            |
| 点「下一首」        | 序号 +1，切到下一 P                  |
| 点「上一首」        | 序号 −1                         |
| 点播放模式按钮       | 循环切换：顺序 → 列表循环 → 单曲 → 随机 → 顺序 |
| 切到「单曲」后点「下一首」 | **应该换歌**，不是原地重播               |


> 队列默认收起是有意的：多 P 视频动辄上百条，全展开会把控制区顶出屏幕。

### 步骤 12 — 长按操作菜单

回搜索页，**长按**任意一条结果。


| 检查点   | 期望                                       |
| ----- | ---------------------------------------- |
| 弹出内容  | 底部弹出菜单，顶部是该视频标题，下面四项：**加入歌单 / 下一首播放 / 复制链接 / 查看分 P** |
| 点「下一首播放」 | 队列数 +1（`队列 3 / 3` → `队列 3 / 4`），**当前序号不变、正在播的这首不被打断** ← 关键 |
| 点「复制链接」 | 粘贴到任意输入框，应是 `https://www.bilibili.com/video/BVxxxx` |
| 点「查看分 P」 | 展开该视频的分 P 列表（单 P 视频也展开，不直接起播）             |


> 「下一首播放」若把正在播的歌顶掉了，说明插入后没修正当前下标。

### 步骤 13 — 本地歌单：选择加入与拖拽重排

**先验「加到哪个歌单由你决定」。** 回搜索页长按结果 →「加入歌单」。


| 场景     | 期望                                  |
| ------ | ----------------------------------- |
| 一个歌单都没有 | 直接进「新建歌单并加入」，填名字后创建并加入（**不再凭空造一个「我的歌单」**）|
| 已有歌单   | 弹出歌单列表 + 「＋ 新建歌单」，**选中哪个就加到哪个**      |
| 点「＋ 新建歌单」 | 切到填名字界面，创建后条目落进新歌单                |
| 点「取消」  | 什么都不加                               |


**再验歌单详情。** 底部「音乐库」→ 点进歌单。


| 检查点          | 期望                          |
| ------------ | --------------------------- |
| 标题           | 「歌单名 · N 首」                 |
| 条目           | 每条带**封面**、标题、UP 主、**时长（`mm:ss`）** |
| 提示           | 列表上方有「长按条目可拖动排序」            |
| 点条目          | **整个歌单作为队列播放**，从该条开始         |
| 改名 / 删除 / 移除 | 立即生效                        |


**最后验拖拽重排**（至少先加 3 首）。**长按**某一条不放，**拖到另一个位置再松手**。


| 检查点    | 期望                    |
| ------ | --------------------- |
| 拖动中    | 被拖的行浮起（底色变化），跟着手指走    |
| 松手     | 落到目标位置，列表顺序立即变化       |
| **杀进程重开再进该歌单** | **顺序保持** ← 关键，证明写进了数据库而不只是动画 |


```bash
adb shell am force-stop com.biliseek.debug
adb shell am start -n com.biliseek.debug/com.biliseek.app.MainActivity
```

> 用命令模拟拖拽（`swipe` 不会触发长按）：
>
> ```bash
> # 模拟器：draganddrop 够用
> adb shell input draganddrop 400 485 400 870 2000
>
> # 真机：draganddrop 的按下时长越不过 Compose 的长按阈值，实测无效，
> # 必须自己拆成「按下 → 停 1 秒 → 逐步移动 → 抬起」
> adb shell "input motionevent DOWN 400 690; sleep 1; \
>   for y in 720 780 850 920 990 1060 1130 1200 1260 1290; do \
>     input motionevent MOVE 400 \$y; done; \
>   input motionevent UP 400 1290"
> ```

### 步骤 14 — 首页空状态

回搜索页，**把搜索框的字清空**。


| 检查点   | 期望                    |
| ----- | --------------------- |
| 搜索历史  | 出现关键词标签，每个带 ✕，右上有「清空」 |
| 最近播放  | 出现刚才播过的条目，带**封面**，进度显示为 `01:04 / 02:52` 形式 |
| **时长** | **右边不应是 `00:00`** ← 时长回写生效的标志 |
| 播放热力  | 出现小方块                 |
| 点历史标签 | 直接用该关键词搜索             |
| 点 ✕   | 删掉该条历史                |


> 这些全是**你自己的行为数据**，没有算法推荐——这是「没有推荐页」的产品身份。

### 步骤 15 — AV 号 / BV 号 / 短链直达

在搜索框里依次粘贴下面几种输入，每次点「搜索」。


| 输入                                          | 期望                                    |
| ------------------------------------------- | ------------------------------------- |
| `av170001`                                  | **直接起播**，标题显示 `BV17x411w7KC`（本地换算，不走搜索）|
| `https://b23.tv/BV17x411w7KC`               | 展开短链后直接起播                             |
| `https://www.bilibili.com/video/BV1Q541167Qg` | 直接起播                                  |
| `看看这个 https://b23.tv/BV17x411w7KC 快来看`      | 混着说明文字也能挑出链接并起播                       |


日志窗口应出现对应的 `playurl?bvid=BV17x411w7KC`。

> `av170001 → BV17x411w7KC` 是**本地算出来的**，不该为了拿 BV 号多打一次网络请求。
> 换算错了的表现是 pagelist 404、播不出来。

### 步骤 16 — 接住外部分享

**真机上**：在 B 站 App 里找个视频 → 分享 → 选 BiliSeek。
或在浏览器里打开一个 b23.tv 链接 → 选 BiliSeek 打开。

**模拟器上**用命令模拟：

```bash
# 模拟「分享到」（ACTION_SEND）
adb shell am start -a android.intent.action.SEND -t text/plain \
  --es android.intent.extra.TEXT "'【标题】 - 哔哩哔哩 https://b23.tv/BV17x411w7KC 快来看'" \
  com.biliseek.debug

# 模拟浏览器点链接（ACTION_VIEW）
adb shell am start -a android.intent.action.VIEW \
  -d "https://www.bilibili.com/video/BV1Q541167Qg" com.biliseek.debug
```


| 场景                | 期望                       |
| ----------------- | ------------------------ |
| App 没开时分享         | 冷启动后**直接起播**             |
| **App 已经开着时再分享一次** | **同样直接起播** ← 最容易漏的一处     |
| 连续分享两个不同视频        | 第二个能切过去，不是「点了没反应」        |


> 「第一次能用、第二次没反应」是这里的经典失败模式：只处理了 `onCreate` 没处理 `onNewIntent`。
> 另一种失败是**完全没反应**——起播请求赶在播放器连上之前发出，被静默丢掉了。

### 步骤 17 — 后台与锁屏

播放中按 **Home 键**回桌面。


| 检查点     | 期望              |
| ------- | --------------- |
| 声音      | 继续播放            |
| 通知栏（下拉） | 出现媒体控制卡片，可暂停/继续 |


测锁屏前，模拟器需要先启用锁屏（AVD 默认关掉了）：

```bash
adb shell locksettings set-disabled false
```

然后按电源键锁屏、再唤醒（不解锁）。


| 检查点     | 期望            |
| ------- | ------------- |
| 锁屏界面    | 出现媒体控制卡片，标题正确 |
| 点卡片上的暂停 | 播放暂停          |


### 步骤 18 — 画中画

回到 App，切到**看模式**，然后按 Home 键。


| 检查点       | 期望                 |
| --------- | ------------------ |
| PiP 窗口    | 出现小窗，**里面有画面不是黑的** |
| 点小窗回到 App | 恢复内联看模式，画面连续       |


> PiP 黑屏是最典型的失败信号，说明「进后台回落音频」的判定误伤了 PiP。

⚠️ **真机上先确认系统给了权限**，否则根本进不去小窗（音频会继续播，看着像「回落正常」）：

```bash
adb shell cmd appops get com.biliseek.debug PICTURE_IN_PICTURE     # 期望 allow
```

返回 `deny` 就手动开：**设置 → 应用管理 → BiliSeek → 权限 → 画中画**。
国产 ROM（实测 ColorOS / Android 16）默认不给，且**不允许用 adb 改**——
`cmd appops set` 会报 `SecurityException: uid 2000 does not have MANAGE_APP_OPS_MODES`。

### 步骤 19 — 续播

播放某条内容 **至少 30 秒**（位置每 5 秒回写一次），然后：

```bash
adb shell am force-stop com.biliseek.debug
adb shell am start -n com.biliseek.debug/com.biliseek.app.MainActivity
```


| 检查点      | 期望                    |
| -------- | --------------------- |
| 首页「最近播放」 | 显示刚才那条，带保存的秒数         |

### 步骤 21 — 设置页（M8 新增）

| 场景 | 期望 |
| ---- | ---- |

### 断网表现与错误重试

**要测到真东西，得先把凭据清掉**——否则凭据还在缓存里，走不到出问题的那条路径：

```bash
adb shell pm clear com.biliseek.debug
adb shell pm grant com.biliseek.debug android.permission.POST_NOTIFICATIONS
adb shell am start -n com.biliseek.debug/com.biliseek.app.MainActivity
sleep 15                                       # 让后台预热跑进退避
adb shell cmd connectivity airplane-mode enable
```

然后在界面上点播放（或发一个链接进去）。


| 操作            | 期望                                        |
| ------------- | ----------------------------------------- |
| 断网后杀掉 App 重开  | **界面完整、搜索框能输入**，不白屏不 ANR                  |
| 断网时点播放        | **5 秒内**出现「取流失败」+「**重试**」按钮，不是无限转圈        |
| 断网时搜索         | 出现「网络不可用」+「重试」，**不是白屏**                   |


> 这条曾经要等约 85 秒——后台预热与用户请求共用一份重试预算，用户只能排队干等。
> 现在两条路径预算分开，前台**只试一次就报错**。

用日志确认「没有排队」：

```bash
adb logcat -d -v time | grep -E "FOREGROUND|BACKGROUND"
```

应看到两条链**各走各的**（前台只有「第 1 次」，后台在自己按 1/2/4/8 秒退避）：

```
07:21:05.117 W BiliSeekAuth: 凭据获取失败（第 1 次，FOREGROUND）：Unable to resolve host
07:21:05.423 W BiliSeekAuth: 凭据获取失败（第 5 次，BACKGROUND）：Unable to resolve host
```

**恢复网络后点「重试」**：

```bash
adb shell cmd connectivity airplane-mode disable
```


| 操作     | 期望                                    |
| ------ | ------------------------------------- |
| 点「重试」  | 一次点击内完成「重新种植凭据 → 取流 → 起播」             |
| 日志     | `风控凭据种植完成` 紧跟 `MPD 组装完成`              |


> 若「重试」按钮被软键盘挡住，先按一次返回键收键盘。

### 错误分类与「不该出现的重试按钮」


| 错误                | 文案                    | 是否给「重试」按钮       |
| ----------------- | --------------------- | --------------- |
| 网络不可用             | 「网络不可用」               | ✅ 给             |
| 设备凭据失效（-412）      | 「设备凭据已失效，已重新种植」       | ✅ 给             |
| 凭据未激活             | 「设备凭据尚未激活…」           | ✅ 给             |
| 搜索无结果             | 「没有找到「xxx」」           | ❌ **不给**（重试也没有） |
| **触发风控（-352）**    | 「请求太频繁，B 站暂时拦截了搜索」    | ❌ **绝不给** ← 硬判据 |


> **别为了看这条截图去猛刷搜索。** `-352` 的正确处置就是等，
> UI 不给按钮正是为了避免用户猛戳把临时限流拖成长期封禁。这条靠单测锁定，不实触发。

### 流量对比（验证「听模式省流量」）

⚠️ 模拟器的流量统计是**粗粒度轮询**，不强制刷新会一直读到 0：

```bash
adb shell dumpsys package com.biliseek.debug | grep appId      # 取 uid
adb shell dumpsys netstats --poll                              # 必须先这句
adb shell dumpsys netstats detail | grep -A 12 "uid=<你的uid>"
```

分别在听模式和看模式各播 1 分钟，对比 `rb=` 增量。预期是**量级差异**（实测约 160 倍）。

## C5. 界面功能测试

**先把 Part B 的 B5 表格（步骤 1–23）在手机上走一遍**，确认基础功能正常。手机可以拿在手上操作，不用守在电脑前。

## C6. 移动场景专项

**这是走无线这条路径的真正理由。** 以下场景需要你带着手机走动。

### 步骤 24 — 边走边听

戴上耳机，播放音频，**把手机装进口袋走动 10 分钟**。


| 检查点       | 期望           |
| --------- | ------------ |
| 播放        | 全程不中断        |
| 息屏后       | 继续播放         |
| 中途掏出手机看锁屏 | 媒体控制卡片在，信息正确 |


### 步骤 25 — 网络切换

播放中从 Wi-Fi 覆盖区走到室外（切到移动网络）。


| 检查点  | 期望              |
| ---- | --------------- |
| 切换瞬间 | 播放可能短暂缓冲，但应自动恢复 |
| 不应   | 永久卡死、报错退出、静音    |


反向再试一次（4G 走回 Wi-Fi）。

### 步骤 26 — 弱信号与断连

进电梯 / 地下车库 / 信号盲区。


| 检查点     | 期望                  |
| ------- | ------------------- |
| 缓冲区内    | 继续播放不受影响            |
| 缓冲耗尽    | 卡住但**不崩溃**          |
| 出电梯恢复信号 | **自动续上**，不需要手动重新点播放 |


### 步骤 27 — 飞行模式

播放中打开飞行模式 20 秒，再关掉。


| 检查点    | 期望          |
| ------ | ----------- |
| 开飞行模式时 | 缓冲耗尽后卡住，不崩溃 |
| 关飞行模式后 | 自动恢复播放      |


### 步骤 28 — 息屏长播

息屏播放 **30 分钟**，中途不动手机。


| 检查点 | 期望                             |
| --- | ------------------------------ |
| 播放  | 不中断、不被系统杀掉                     |
| 耗电  | 听模式下应明显低于看模式（设置 → 电池 → 用量详情对比） |


> 这条特别重要：BiliSeek 的定位是「默认只听」，用户绝大多数时间就是息屏放口袋里。


# 附录 1：日志查看详解

## 1.1 App 的四个日志 tag


| Tag               | 内容                              | 什么时候看            |
| ----------------- | ------------------------------- | ---------------- |
| `BiliSeekAuth`    | 风控凭据的种植、恢复、失败（**带 FOREGROUND / BACKGROUND 标注**） | 搜索没结果、启动异常、报错太慢 |
| `BiliSeekPlayUrl` | 取流、MPD 组装、URL 缓存命中              | 点了播不出来           |
| `BiliSeekPlayer`  | **EventLogger**——轨道选择、解码器、缓冲、首帧 | 验证切看是否真的省流量      |
| `BiliSeekRefresh` | 登录态续期的检查结果                      | 怀疑掉登录            |
| `BiliSeekHttp`    | 完整 HTTP 请求与响应头                  | 接口报错、怀疑签名/Cookie |


## 1.2 基本用法

```bash
# 实时看（推荐先清屏，避免历史日志干扰）
adb logcat -c && adb logcat -s BiliSeekPlayer:V

# 同时看多个 tag
adb logcat -s BiliSeekAuth:V BiliSeekPlayUrl:V BiliSeekPlayer:V

# 只导出已有日志不持续输出（-d = dump）
adb logcat -d -s BiliSeekAuth:V

# 存到文件事后分析
adb logcat -d > /tmp/biliseek.log

# 只看本 App 进程的全部日志
adb logcat --pid=$(adb shell pidof com.biliseek.debug)

# 看崩溃
adb logcat -d -s AndroidRuntime:E | grep -A 20 FATAL
```

## 1.3 关键日志长什么样

**启动时的凭据（首次）**

```
D BiliSeekAuth: buvid 激活: code=0
D BiliSeekAuth: 风控凭据种植完成
```

**启动时的凭据（后续）**

```
D BiliSeekAuth: 凭据从本地恢复，跳过网络请求
```

**取流成功**

```
D BiliSeekPlayUrl: MPD 组装完成：视频轨 6 条，音频轨 3 条
```

**重播命中缓存**（不应重复请求 playurl）

```
D BiliSeekPlayUrl: playurl 命中缓存 BV1GJ411x7h7:137649199:false
```

**断网时的两条重试路径**（关键：前台只有「第 1 次」，且不排在后台后面）

```
W BiliSeekAuth: 凭据获取失败（第 1 次，FOREGROUND）：Unable to resolve host ...
W BiliSeekAuth: 凭据获取失败（第 5 次，BACKGROUND）：Unable to resolve host ...
```

若看到前台也在「第 2 次、第 3 次…」，说明快慢预算没拆开，错误会浮现得很慢。

**登录态续期检查**

```
D BiliSeekRefresh: 启动时检查登录态续期：NotLoggedIn      ← 未登录
D BiliSeekRefresh: 启动时检查登录态续期：NotConfigured     ← 公钥未填（当前预期状态）
D BiliSeekRefresh: 启动时检查登录态续期：NotNeeded        ← 服务端说还不用刷
D BiliSeekRefresh: 登录态已续期                          ← 刷新成功
```

## 1.4 验证「听模式真的没下载视频」

这是最容易被表象骗过去的一项——**画面消失不等于视频轨被禁用**。

```bash
adb logcat -c && adb logcat -s BiliSeekPlayer:V
```

然后在 App 里切听/看，观察：

**切到看模式时**

```
videoEnabled            [eventTime=..., mediaPos=44.66]
videoDecoderInitialized [... c2.goldfish.hevc.decoder]
renderedFirstFrame      [... Surface(...)]
```

**退回听模式时**

```
videoDisabled  [eventTime=..., mediaPos=79.75]
rendererReady  [... rendererIndex=0, video, false]     ← 视频渲染器已释放
```

**轨道选择表**（EventLogger 会打印）：

```
tracks [...
  group [ id=1
    [ ] Track:0, mimeType=video/avc, res=320x142      ← [ ] = 未选中
    [X] Track:1, ...                                   ← [X] = 已选中
```

听模式下所有视频轨都应是 `[ ]`。

> 为什么较真：`clearVideoSurface()` 同样会让画面消失，但视频轨可能仍在下载解码——那样省电省流量的承诺一点没兑现。**只有日志能证明。**

## 1.5 系统状态速查

```bash
adb shell dumpsys activity services | grep -A 8 PlaybackService

# 媒体会话（锁屏/通知栏控制的前提）
adb shell dumpsys media_session | grep -E "package=com.biliseek|state=PlaybackState"
```

## 1.6 切换无缝的判据在日志里，不在界面上

早期版本在播放页显示过一张自检卡片（`✓ 切换无缝：听 → 看 / buffering 0 / seek 0`）。
**这个卡片在 M3 的播放器容器重构里已被移除**，界面上不再有它——
诊断数据仍在产出（`PlaybackState.lastSwitch`），但没有 UI 消费。

所以判据落在日志上，见[步骤 8](#步骤-8--一键切看核心卖点)：

```bash
adb logcat -c && adb logcat -d -s BiliSeekPlayer:V > /tmp/switch.log
grep -ic buffering /tmp/switch.log              # 须为 0
grep -ic positionDiscontinuity /tmp/switch.log  # 须为 0
```

> 想把判据搬回界面也行——`lastSwitch` 是现成的，只差一个 Composable。

# 附录 2：排查手册


| 现象                              | 优先排查                                                           |
| ------------------------------- | -------------------------------------------------------------- |
| 搜索一直没结果、也没错误                    | buvid 未激活。`adb shell pm clear` 后重启，看日志有无「buvid 激活: code=0」     |

| 接口返回 `-352`                     | 触发风控。**别反复重试**，等一会儿再用                                          |
| 切看时声音断一下                        | 播放源被重建了。数日志里的 buffering / positionDiscontinuity，须为 0           |
| **换内容后黑屏、无封面、按钮写着「退回听」**       | 呈现态没跟着起播复位。`play()` 必须把「禁轨 + 清 surface + `presentation = NONE`」三件事一起做，只做第一件就是这个症状 |
| 关了画面但流量照跑                       | 只清了 surface 没禁用视频轨。看 `videoDisabled` 日志                        |
| PiP 窗口黑屏                        | 「进后台」判定误伤了 PiP                                                 |
| 切页签时声音中断                        | MiniPlayer 被卷进了导航重组                                            |
| 点了播放没反应                         | 可能续播到了结尾。看日志有无 `state ... ENDED`                               |
| **封面全是灰块**                       | 图片请求没带 Referer，CDN 403。看 `BiliSeekHttp` 里 `i0.hdslb.com` 的响应码 |
| **进度条一松手就弹回**                    | UI 直接绑了播放器状态，被 250ms 轮询覆盖；应有本地拖动态                              |
| **拖完杀进程位置丢了**                    | `seekTo` 没做强制回写，等着 5 秒节流                                       |
| **断网时报错要等很久**                    | 快慢重试预算没拆开。日志里前台若出现「第 2 次」以上即是                                  |
| **分享进来第一次能用第二次没反应**              | 只处理了 `onCreate`，漏了 `onNewIntent`                               |
| **分享进来完全没反应、也不报错**                | 起播请求赶在播放器绑定完成前发出被丢弃；`play()` 应自己补 `connect()` 而不是静默返回          |

| **拖拽歌单没反应**                      | 落点邻居没有先把被拖动项摘掉，算出的中值仍落回原位                                      |
| **风控时出现了「重试」按钮**                 | 严重。`-352` 必须 `retryable == false`，猛戳会把限流拖成封禁                    |
| `adb devices` 显示 unauthorized   | 手机上没点授权，重新拔插看弹窗                                                |
| `adb devices` 显示 no permissions | udev 规则缺失，`sudo apt install android-sdk-platform-tools-common` |
| 无线调试连不上                         | 配对端口与连接端口不是同一个；确认在同一 Wi-Fi                                     |
